Aula 05 — Colaboração com Git

Versionamento de código e de prompts, fluxo de trabalho em equipe

Projeto Integrado de Introdução à IA · PUC-Rio

Vocês já têm o escopo. Agora, o time precisa trabalhar junto

A partir de hoje, cada pessoa do grupo mexe no mesmo projeto ao mesmo tempo — sem Git, isso vira uma pasta cheia de projeto_final_v3_ultimo_DEFINITIVO.zip.

Prompts são código

No seu projeto, o prompt do sistema, a configuração do agente e o workflow do n8n são artefatos versionáveis, tanto quanto qualquer função Python. Se mudou o prompt e a saída do agente ficou pior, você precisa conseguir voltar atrás.

Por isso: prompts salvos em arquivo de texto no repositório (não só colados num chat), exportações de workflow do n8n commitadas como JSON.

Os três estados de um arquivo

Working Directory

O que você está editando agora, ainda não registrado

Staging Area

git add — o que vai entrar no próximo commit

Repository

git commit — registrado no histórico do projeto

Fluxo básico, do zero

git clone https://github.com/seu-time/projeto-pi-ia.git
cd projeto-pi-ia

# depois de editar arquivos...
git status                 # o que mudou?
git add prompts/sistema.txt
git commit -m "feat: ajusta tom do prompt do agente de triagem"
git push origin main

Trabalhando em paralelo sem pisar no time

Regra do curso: nunca commitar direto na main. Cada mudança nasce numa branch.

git checkout main
git pull origin main
git checkout -b feature/agente-triagem

# ... trabalha, testa, commita ...

git push origin feature/agente-triagem
# abrir Pull Request no GitHub

Pull Request: o momento de revisão

  • Título e descrição claros: o que mudou e por quê
  • Se mudou um prompt: cole um exemplo de saída antes/depois
  • Peça pra pelo menos 1 colega revisar antes do merge
Revisão de prompt funciona como revisão de código: um colega lendo pode pegar um caso que você não testou.

Conflitos de merge

Acontece quando duas pessoas editam a mesma parte do mesmo arquivo. O Git marca o trecho conflitante:

<<<<<<< HEAD
Você é um assistente formal e objetivo.
=======
Você é um assistente amigável e descontraído.
>>>>>>> feature/tom-casual

Resolver = decidir junto qual versão (ou uma combinação) fica, apagar as marcações, e commitar.

Quest: Fluxo Git Profissional

  1. Criem o repositório do projeto (se ainda não existe) com um README.md baseado no canvas da aula passada
  2. Cada integrante cria uma branch e faz pelo menos 1 commit
  3. Abram Pull Requests e revisem o PR de um colega
  4. Façam merge só depois da aprovação
Depois do merge: enviar o link do PR revisado →
