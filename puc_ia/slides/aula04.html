O erro mais comum: começar pela tecnologia

“Vamos usar um agente de LLM para...” é a pergunta errada de partida. A pergunta certa: quem tem qual problema, e por quê?

Tecnologia é meio, não fim. Um MVP bom resolve um problema real — a IA aparece só onde ela é a ferramenta certa.

AI Canvas: Prediction, Judgment, Action

Framework para decompor uma decisão em três partes, útil pra saber onde a IA realmente ajuda:

Prediction

O que o modelo precisa prever? (Ex.: esse texto é spam?)

Judgment

Dada a previsão, qual decisão humana ela apoia? (Ex.: vale a pena arquivar?)

Action

O que acontece de fato no mundo com essa decisão? (Ex.: e-mail é movido)

Definindo o problema (não a solução)

Complete antes de pensar em tecnologia:

  • Quem sente esse problema, especificamente?
  • Com que frequência isso acontece, e qual o custo de não resolver?
  • Como essa pessoa resolve isso hoje, sem IA?

Escopo de MVP: o que cabe em um sprint

Cabe no Sprint 1

Um fluxo único, ponta a ponta, com dados reais (mesmo que poucos) e uma interface mínima.

Não cabe ainda

Múltiplos usuários, autenticação robusta, escala, fine-tuning de modelo próprio.

Regra prática: se o MVP não roda de ponta a ponta com um exemplo real até a Apresentação Sprint 1, o escopo está grande demais.

Atividade: Canvas do seu projeto

  1. Em grupo, preencham o AI Canvas do problema que vocês escolheram (Prediction / Judgment / Action)
  2. Escrevam uma frase de escopo: “Nosso MVP vai [ação] para [quem], usando [dado/entrada]”
  3. Listem 3 coisas que não entram no Sprint 1
Levem esse canvas pronto pra próxima aula (Git) — ele vira o README inicial do repositório do projeto.
