2) Como o LLM funciona

  1. Tokenização: quebra o texto em pedaços (tokens).
  2. Embeddings: transforma cada token em vetor numérico.
  3. Contexto: usa os tokens anteriores para prever o próximo.
  4. Probabilidades: calcula as palavras mais prováveis.
  5. Decodificação: escolhe a próxima palavra e repete.

Tokenização & Embeddings

  • Tokenização por sub‑palavras: "cachorros" → "cach" + "orros".
  • Embeddings: números que capturam semelhança de significado.
  • Palavras parecidas ficam com vetores próximos.
// Exemplo (conceitual)
Texto: "O gato dorme"
Tokens: ["O", " gato", " dorme"]
Embeddings: [[...],[...],[...]] → usados para prever o próximo token

Decodificação (como a saída é escolhida)

  • Greedy: escolhe sempre a mais provável (pode ficar repetitivo).
  • Top‑k: sorteia entre as k mais prováveis.
  • Top‑p (nucleus): sorteia dentro do menor conjunto com soma ≥ p.
  • Temperatura: aumenta/diminui aleatoriedade.
// Pseudocódigo
probs = LLM.probabilidades(próximo_token)
probs = nucleus_filter(probs, p=0.9)
proximo = sample(probs, temperatura=0.7)

3) A mágica: dados & treinamento

  • Pré‑treinamento: aprende a prever próxima palavra em bilhões de frases.
  • Curadoria: limpeza de dados, remoção de duplicatas e conteúdo tóxico.
  • Compute: GPUs/TPUs por dias ou semanas; custo alto.

O modelo "absorve padrões" do texto; não "entende" como humanos.

Fine‑tuning, Instruções & RLHF

  • SFT (supervisionado): ajusta com pares pergunta→resposta.
  • Instrução: exemplos do tipo "faça X no estilo Y com restrição Z".
  • RLHF: humanos avaliam respostas → modelo aprende preferências (clareza, utilidade, segurança).
// Exemplo de par para SFT
Entrada: "Explique fotosíntese para 9º ano em 120 palavras"
Saída:   "A fotosíntese é o processo pelo qual..."

4) Prompt Engineering — Anatomia de um bom prompt

  • Papel (persona) + tarefa + contexto + formato da saída + critérios.
  • Seja específico sobre público‑alvo, tom e limites (tamanho, tempo).
  • Divida tarefas complexas em etapas e peça verificação.
Você é tutor para calouros.
Tarefa: introduzir LLM em 5 bullets claros.
Formato: bullets; até 90 palavras; tom motivador.
Critérios: sem jargões; 1 exemplo do dia a dia.

Técnica 1 — Role / Persona

Defina um papel para moldar estilo, foco e critério.

Você é um revisor do ENEM.
Avalie o texto abaixo em 3 critérios: coesão, clareza, argumentação.
Dê uma nota 0–10 para cada critério e 2 sugestões de melhoria.

Técnica 2 — Few‑shot (exemplos)

Mostre 1–3 exemplos de entrada→saída para orientar.

Exemplo 1
Pergunta: Capital da França?  Resposta: Paris
Exemplo 2
Pergunta: Capital do Japão?   Resposta: Tóquio
Agora responda:
Pergunta: Capital da Itália?  Resposta:

Técnica 3 — Zero‑shot com restrições

Sem exemplos, mas com regras claras de saída.

Explique o que é overfitting em até 80 palavras.
Público: 1º período. Tom: didático.
Inclua 1 analogia simples e 1 conselho prático.

Técnica 4 — Saída estruturada (JSON/Tabela)

Peça um formato fixo para facilitar uso posterior.

Liste 3 ideias de projeto no JSON:
[
 {"titulo":"...","objetivo":"...","recursos":["..."],"dificuldade":"baixa|média|alta"},
 ...
]

Técnica 5 — Delimitadores & contexto

Forneça trechos entre marcadores; peça para usar apenas o que está ali.

Use somente os trechos entre --- como base.
Se a resposta não estiver nos trechos, diga "não encontrei".
---
[TEXTO 1]
[TEXTO 2]
---

Técnica 6 — Crítica & Refino (Reflexion)

Peça para o modelo criticar e melhorar a própria saída.

Escreva a resposta. Em seguida, gere uma crítica breve
apontando 2 melhorias específicas. Aplique as melhorias
para produzir a versão final.

Técnica 7 — Auto‑verificação / Checklist

Antes de finalizar, valide critérios objetivos.

Revise usando esta checklist:
1) Fatos citados?
2) Passos lógicos?
3) Saída no formato pedido?
Se houver falhas, corrija e mostre a versão final.

5) Chain‑of‑Thought (CoT)

  • Estimule raciocínio em etapas para tarefas de cálculo/planejamento.
  • Para turma iniciante, prefira CoT conciso (3–5 passos).
  • Peça um resumo final destacado.
Problema: Tenho R$80; gasto 35% com livros. Quanto sobra?
"Mostre em 3 passos curtos e destaque a resposta final."
1) 35% de 80 = 28
2) 80 − 28 = 52
3) Sobram R$52 → <RESULTADO>

6) RAG — Retrieval‑Augmented Generation

  • Combina LLM + busca em documentos (ou web).
  • Recupera trechos relevantes e injeta no prompt.
  • Resultados mais atualizados e citáveis.
// Template de RAG
Use apenas os trechos fornecidos abaixo.
Se a resposta não estiver neles, diga "não encontrei".
Cite o trecho usado entre aspas curtas.
---
[TRECHOS RECUPERADOS]
---

Boas práticas: dividir documentos (chunking), indexar com embeddings, evitar trechos irrelevantes.

8) Limitações & cuidados

  • Alucinações: pode inventar dados. Sempre verifique.
  • Viés: reflete os dados de treino; use linguagem inclusiva.
  • Privacidade: evite dados sensíveis em prompts.
  • Janela de contexto: esquece partes longas; resuma e foque.
// Checklist de segurança antes de enviar o prompt
[ ] contém dados pessoais?  [ ] pede fontes?  [ ] formato claro?
Se "sim" para dados pessoais, remova/anonimize antes.

Atividade final (10–15 min)

  1. Em duplas, escolham um tema de interesse.
  2. Preparem pelo menos um prompt usando uma técnica: Role, Few‑shot, Zero‑shot com restrições, Estruturado, Delimitadores, Crítica/Refino ou Checklist.
  3. Peçam CoT conciso (3–5 passos) e um resumo final.
