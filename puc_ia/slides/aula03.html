Da última aula

Vimos LLMs como "cérebros probabilísticos": prompt engineering, Chain-of-Thought, RAG.

Um LLM sozinho só responde. Hoje ele vai agir: consultar ferramentas, chamar APIs, tomar decisões em etapas.

O que é um Agente de IA?

Um agente combina um LLM com um loop de decisão: ele observa o estado do mundo, decide uma ação, executa, observa o resultado, e repete.

LLM comum

Prompt → Resposta. Uma única passada, sem memória de ação.

Agente

Prompt → Pensa → Age → Observa → Pensa de novo → ... → Resposta final.

Arquitetura ReAct (Reason + Act)

Um dos padrões mais usados para agentes: alterna explicitamente entre raciocínio (texto livre) e ação (chamada de ferramenta).

Pergunta: Qual a temperatura em Copacabana agora, em Fahrenheit?

Thought: Preciso da temperatura atual em Copacabana. Vou usar a ferramenta de clima.
Action: buscar_clima("Copacabana, RJ")
Observation: 28°C, céu limpo

Thought: A pergunta pede Fahrenheit. Preciso converter.
Action: calcular("28 * 9/5 + 32")
Observation: 82.4

Thought: Já tenho a resposta final.
Answer: Está 82.4°F em Copacabana agora.

Por que isso importa?

  • LLMs erram em contas e em fatos recentes — ferramentas externas resolvem isso
  • Separar "pensar" de "agir" torna o processo auditável: dá pra ver onde o agente errou
  • É a base de praticamente todo produto de "IA agêntica" que existe hoje

De agentes de código a low-code

Dá pra programar um agente ReAct em Python do zero. Mas, pra prototipar rápido — e pra quem não é dev — ferramentas low-code de automação conectam LLMs a APIs visualmente, sem escrever o loop manualmente.

Hoje: n8n — automação visual de workflows (nós conectados por setas), com suporte nativo a chamadas de LLM.

Anatomia de um workflow no n8n

Trigger

O que inicia o fluxo: um Webhook, um horário agendado, um formulário.

Processamento

Nós de HTTP Request, código, condicionais — incluindo chamar um LLM.

Saída

Responder o webhook, enviar e-mail, escrever numa planilha.

Rodando um LLM localmente

Antes de automatizar, precisamos de um LLM rodando na sua própria máquina — sem depender de API paga.

FerramentaComo funciona
OllamaBaixa e roda modelos abertos (Llama, Mistral, Gemma...) localmente, expõe uma API HTTP em localhost:11434
LM StudioInterface gráfica para rodar modelos locais, também expõe API compatível com OpenAI
Quest “Rodar uma LLM local”: instale o Ollama, baixe um modelo (ollama pull llama3.2) e converse com ele pelo terminal (ollama run llama3.2). Enviar comprovação →

Exemplo: chamando o LLM local via HTTP

curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "Resuma em uma frase o que é um agente ReAct.",
  "stream": false
}'

Essa é exatamente a chamada que o n8n vai fazer por dentro do workflow — só que através de um nó visual "HTTP Request", sem escrever código.

Quest: Montar um fluxo no n8n

  1. Suba o n8n localmente: puc_ia/n8n/setup.sh (detecta Docker ou usa npx n8n)
  2. Um workflow de exemplo já vem importado: Webhook → chama o LLM local → responde
  3. Edite o workflow: troque o prompt, adicione um passo extra (ex.: outro nó HTTP, uma condicional)
  4. Teste enviando uma requisição pro webhook e veja a resposta do seu agente
Veja puc_ia/n8n/README.md pra instruções completas. Enviar comprovação →

Limitações a ter em mente

  • Agentes podem entrar em loops (repetir a mesma ação sem convergir)
  • Cada "pensamento" é uma chamada de LLM — custo e latência somam rápido
  • Ferramentas mal descritas levam a ações erradas: a descrição da ferramenta importa tanto quanto o código dela

Para o projeto integrado

Pense em uma automação real que ajudaria o seu projeto: um agente que triagem mensagens, que resume documentos, que consulta uma API e decide uma ação. Você vai usar essa mesma lógica de agente + ferramentas no MVP.
