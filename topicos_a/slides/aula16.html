Interpretability with Grad-CAM

Thiago Medeiros

Seeing where the network looks — and when this can fool you

Goals for today

  • Understand the landscape of attribution methods (gradients, perturbations, CAM-family).
  • Derive and implement Grad-CAM for CNN classifiers.
  • Use Grad-CAM to debug models (spurious cues, dataset bias, failure cases).
  • Know the limitations: faithfulness vs plausibility, resolution, and failure modes.

Format Lab: implement a minimal Grad-CAM + analyze cases (correct vs incorrect).

1. Why interpretability?

Three practical reasons

  • Debugging: “is the model using the right signal?”
  • Data issues: shortcut learning, label noise, leakage, spurious backgrounds
  • Communication: explainability artifacts for reports / stakeholders
Watch out: a “nice-looking heatmap” does not imply the model is right or robust.

A useful mental model: plausibility ≠ faithfulness.

Methods (quick taxonomy)

By mechanism

  • Perturbation: occlusion, deletion/insertion curves
  • Gradients: saliency, integrated gradients, SmoothGrad
  • CAM-family: CAM, Grad-CAM, Grad-CAM++, Score-CAM
  • Probes: linear probes on hidden states

Today focus on CAM-family: cheap, fast, works well for CNNs.

When you need stronger evidence, add a perturbation sanity check.

2. Grad-CAM: core idea

Setup

  • Pick a class score: \(y^c\)
  • Pick last conv layer feature maps: \(A^k\)
  • Use gradients to estimate how much each channel matters

Intuition If changing \(A^k\) changes \(y^c\), that channel is relevant.

Backbone → last conv activations → gradients w.r.t. class score → heatmap.

Grad-CAM equations

Compute channel weights using global-average pooled gradients:

$$\alpha_k^c = \frac{1}{Z} \sum_i \sum_j \frac{\partial y^c}{\partial A^k_{ij}}$$

Combine channels and keep only positive evidence:

$$L^c_{\text{Grad-CAM}} = \mathrm{ReLU}\left( \sum_k \alpha_k^c A^k \right)$$

Two key moves: (1) gradients define channel importance; (2) ReLU filters negative evidence (what argues against class \(c\)).

What you actually get

  • A low-resolution spatial map (same size as the chosen conv layer)
  • Upsampled to image size (bilinear)
  • Displayed as a heatmap overlay (purely a visualization choice)
Important: Grad-CAM answers “where features that support class \(c\) occur” — not “what pixels are causally necessary”.

Case study checklist (when you see a heatmap)

  • Is it stable? does small noise/augmentation change it dramatically?
  • Does it localize the object? or a watermark / background texture?
  • Does masking the highlighted area reduce the score?
  • Does masking a non-highlighted area keep the score?
Principle: pair an attribution map with a perturbation test.

4. Minimal Grad-CAM in PyTorch

Core steps: capture activations, capture gradients, compute weights, build CAM, upsample, normalize.

import torch
import torch.nn.functional as F

class GradCAM:
    def __init__(self, model, target_layer):
        self.model = model.eval()
        self.target_layer = target_layer
        self.activations = None
        self.gradients = None

        def fwd_hook(_, __, out):
            self.activations = out.detach()

        def bwd_hook(_, grad_in, grad_out):
            # grad_out is a tuple; grad_out[0] matches layer output
            self.gradients = grad_out[0].detach()

        self.target_layer.register_forward_hook(fwd_hook)
        self.target_layer.register_full_backward_hook(bwd_hook)

    @torch.no_grad()
    def _normalize(self, cam):
        cam = cam - cam.min()
        cam = cam / (cam.max() + 1e-8)
        return cam

    def __call__(self, x, class_idx=None):
        self.model.zero_grad(set_to_none=True)
        logits = self.model(x)          # [B, C]
        if class_idx is None:
            class_idx = logits.argmax(dim=1)

        score = logits[0, class_idx]    # scalar
        score.backward()

        A = self.activations[0]         # [K, H, W]
        G = self.gradients[0]           # [K, H, W]
        weights = G.mean(dim=(1,2))     # [K]

        cam = (weights[:, None, None] * A).sum(dim=0)  # [H, W]
        cam = F.relu(cam)
        cam = self._normalize(cam)

        cam = F.interpolate(cam[None, None], size=x.shape[-2:], mode="bilinear", align_corners=False)
        return cam[0,0]

Didactic implementation; production code should handle batching, AMP, and hook cleanup.

Overlay + sanity checks

# 1) Overlay (visualization)
heat = cam.cpu().numpy()                 # [H, W] in [0,1]
img  = x[0].permute(1,2,0).cpu().numpy()  # normalized tensor → convert back for display

# 2) Perturbation test (faithfulness-ish)
def mask(img, heat, t=0.6):
    m = (heat > t).astype(img.dtype)[..., None]
    return img * (1 - m)                 # delete highlighted pixels

# 3) Two quick sanity checks
# (a) randomize model weights → map should change a lot
# (b) randomize labels / class index → map should differ from the original
Sanity checks matter: some saliency methods can look plausible even when the model is randomized.

Lab: Grad-CAM + case analysis

Setup

  • Use a pretrained ResNet-50 (torchvision)
  • Target layer: last conv block (e.g., layer4[-1].conv3)
  • Pick 3–5 real images (phone photos work)

Deliverable a short report with 10 examples + takeaways.

What to do

  1. Run inference → record top-1 / top-5
  2. Compute Grad-CAM for top-1
  3. Collect 5 correct + 5 incorrect
  4. For each: hypothesize the cue used (object part, texture, background)
  5. Validate with a masking perturbation

Common patterns to look for

Healthy-ish

  • Focus on object parts (head/wheels/logo)
  • Stable map under mild augmentations
  • Masking focus → score drops

Red flags

  • Focus on borders, watermarks, timestamps
  • Focus on background textures (snow, grass, sky)
  • Map does not change when class changes
Takeaway: interpretability is a diagnostic tool, not a proof of correctness.

Wrap-up

  • Grad-CAM is fast and useful for CNN debugging.
  • Always pair heatmaps with a perturbation sanity check.
  • Next: robustness + dataset shift + calibration (and why interpretability alone is not enough).
