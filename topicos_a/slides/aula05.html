1. Anatomy of Training

Every Deep Learning script, no matter how complex the architecture, essentially follows the exact same skeleton.

# --- Initialization Phase ---
1. Setup Hyperparameters (Learning Rate, Batch Size, Epochs)
2. Load Data (Initialize PyTorch DataLoaders)
3. Initialize Model, Loss Function, and Optimizer

# --- Execution Phase ---
4. Loop over Epochs:
   4.1. Loop over Batches:
     a. Forward Pass (Make Predictions)
     b. Compute Loss (Evaluate Error)
     c. Backward Pass (Compute Gradients)
     d. Optimizer Step (Update Weights)
     e. Zero Gradients (Reset for next batch)

The "Big 5" Code

Memorize these 5 lines. They are the absolute heartbeat of PyTorch's training mechanism.

# Inside the batch loop:

# 1. Forward Pass
y_pred = model(X_batch)

# 2. Evaluate Loss
loss = criterion(y_pred, y_batch)

# 3. Backward Pass (Gradients)
loss.backward()

# 4. Update Weights
optimizer.step()

# 5. Reset Gradients
optimizer.zero_grad()

Common Pitfall: The Missing Reset

In PyTorch, gradients accumulate (sum up) by default on subsequent backward passes. If you forget optimizer.zero_grad(), step 2's gradients will be added to step 1's gradients, completely ruining the optimization direction!

Note: You can place zero_grad() either at the very beginning of the loop or at the very end. The effect is the same.

2. Epochs vs Batches

We rarely train on the entire dataset simultaneously. We use Mini-Batch SGD to balance memory limits with training stability.

  • Epoch: One complete pass of the entire dataset through the network.
  • Batch Size: The number of samples processed simultaneously before making a single weight update.
  • Iteration (Step): A single weight update (processing one batch).
Example Calculation:
Dataset = 1,000 Images.
Batch Size = 100.
$\rightarrow$ 10 Iterations per Epoch.

Underfitting vs Overfitting

The fundamental trade-off in Machine Learning. It tells us if the model is learning general rules or just memorizing the training data.

State Symptoms (Metrics) Root Cause Common Solutions
Underfitting High Training Loss.
High Validation Loss.		 Model is too simple (low capacity) to capture patterns. Add layers/neurons.
Train for more epochs.
Decrease regularization.
Overfitting Very Low Training Loss.
Rising Validation Loss.		 Model is too complex and is memorizing statistical noise. Add Regularization (Dropout).
Get more data.
Early Stopping.

3. Practicalities: Hyperparameters

Deep Learning is often jokingly called "Alchemy" because these numbers require empirical tuning.

Learning Rate ($\eta$ or lr)

The most critical hyperparameter to tune.

  • Too high: Model diverges (Loss becomes NaN).
  • Too low: Unbearably slow convergence.
  • Rule of Thumb: Start at $3e^{-4}$ (known as Andrej Karpathy's constant for Adam).

Batch Size & Optimizer

  • Batch Size: Usually 32, 64, or 128. Powers of 2 fit GPU memory architecture better. Smaller batches offer more regularization (noise).
  • Optimizer Choice:
    • SGD + Momentum: Can reach slightly better ultimate performance, but needs heavy tuning.
    • Adam: Adaptive, highly robust, generally "just works" out of the box.

Saving & Loading Models

Training can take days. We must serialize our trained weights to disk.

# Save weights only (Recommended)
torch.save(model.state_dict(), "weights.pth")


# To Load later for Inference
model = MyModel() # Instantiate architecture

model.load_state_dict(
    torch.load("weights.pth")
)

# ALWAYS set to inference mode!
model.eval()

Why state_dict()?

A state_dict is simply a Python dictionary mapping each layer to its parameter tensor.

Saving just the weights is far safer and more robust than saving the entire Python object, which can break if your code structure changes.
