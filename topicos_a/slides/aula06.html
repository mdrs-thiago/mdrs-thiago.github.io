1. Pathological Curvature

Why does Vanilla Stochastic Gradient Descent (SGD) fail in deep learning?

The "Ravine" Scenario

Imagine a valley in the loss landscape that is:

  • Very Steep in one direction (e.g., $y$-axis).
  • Very Flat in another direction (e.g., $x$-axis).

Because gradients are orthogonal to contour lines, SGD points mostly in the steep direction. This causes the optimizer to overshoot and bounce back and forth wildly across the ravine, making very little progress toward the actual minimum.

SGD vs. Momentum in a Ravine

Red: SGD (Oscillating) | Blue: Momentum (Accelerating)

2. Momentum

Momentum solves the ravine problem by accumulating velocity. It dampens oscillations in steep directions and builds up speed in flat, consistent directions.

$$v_{t+1} = \rho v_t + \nabla L(w_t)$$
$$w_{t+1} = w_t - \eta v_{t+1}$$

Key Parameters

Param Typical Effect
$\eta$ (LR) 0.01 Base step size.
$\rho$ (Momentum) 0.9 Friction/Mass. Determines how fast past velocity decays.

PyTorch Usage

import torch.optim as optim

# Adding momentum to standard SGD
optimizer = optim.SGD(
    model.parameters(), 
    lr=0.01, 
    momentum=0.9
)

3. RMSProp

Root Mean Square Propagation adapts the learning rate for each individual parameter based on its recent gradient magnitude.

The Math

1. Accumulate Squared Gradients:

$$s_t = \beta s_{t-1} + (1-\beta) (\nabla L)^2$$

2. Update Weights:

$$w_{t+1} = w_t - \frac{\eta}{\sqrt{s_t + \epsilon}} \nabla L$$

Intuition

We explicitly divide the gradient by its recent average size.

  • Steep direction: Large $(\nabla L)^2 \rightarrow$ Large $s_t \rightarrow$ Divides by a large number $\rightarrow$ Small update (Dampens oscillation).
  • Flat direction: Small $(\nabla L)^2 \rightarrow$ Small $s_t \rightarrow$ Divides by a tiny number $\rightarrow$ Large update (Speeds up).

4. Adam (Adaptive Moment Est.)

Adam is the current industry standard. It elegantly combines the directional smoothing of Momentum (1st Moment) with the step-size scaling of RMSProp (2nd Moment).

$$m_t = \beta_1 m_{t-1} + (1-\beta_1) \nabla L$$ $\leftarrow$ Momentum (Velocity)
$$v_t = \beta_2 v_{t-1} + (1-\beta_2) (\nabla L)^2$$ $\leftarrow$ RMSProp (Squared)
$$\hat{m}_t = \frac{m_t}{1-\beta_1^t}, \quad \hat{v}_t = \frac{v_t}{1-\beta_2^t}$$ $\leftarrow$ Bias Correction
$$w_{t+1} = w_t - \frac{\eta}{\sqrt{\hat{v}_t} + \epsilon} \hat{m}_t$$ Final Update Rule

Adam Hyperparameters

Param Default Effect
$\eta$ 0.001 Global Learning Rate.
$\beta_1$ 0.9 Decay for Momentum. Controls smoothness of direction.
$\beta_2$ 0.999 Decay for Squared Gradients. Window for variance estimation.
$\epsilon$ 1e-8 Stability. Prevents division by zero.

PyTorch Implementation

Adam is incredibly robust and usually works perfectly with its default parameters out-of-the-box.

import torch.optim as optim

# The only parameter you usually 
# need to tune is the learning rate
optimizer = optim.Adam(
    model.parameters(), 
    lr=3e-4 # Andrej Karpathy's constant
)

Summary

  • SGD: Simple, but oscillates terribly in pathological ravines.
  • Momentum: Fixes oscillation by accumulating velocity ($\rho$), acting like a snowball.
  • RMSProp: Adapts step sizes by scaling updates inversely to the recent standard deviation ($\sqrt{s_t}$).
  • Adam: Does BOTH. It is the gold standard for most Deep Learning tasks today.
  • Most frameworks initialize Adam with perfect default moments ($\beta_1=0.9, \beta_2=0.999$).
