Vision, Kernels, Padding, and Receptive Fields

1. Why MLPs Fail on Images: Parameters

Standard Multi-Layer Perceptrons (Fully Connected Networks) connect every input pixel to every hidden neuron. This creates a catastrophic scaling problem.

The Math of the Curse

  • Consider a tiny RGB image: $200 \times 200$ pixels.
  • Total input features: $200 \times 200 \times 3 = 120,000$.
  • Suppose we want a single hidden layer with $1,000$ neurons.
  • Weights in Layer 1: $120,000 \times 1,000 = \mathbf{120,000,000}$!
Consequence: Hundreds of millions of parameters for a tiny image guarantee severe Overfitting and Out-of-Memory (OOM) errors on modern GPUs.

Dense Connections Explode

Why MLPs Fail: Loss of Spatial Topology

When we flatten a 2D image into a 1D vector to feed an MLP, we completely destroy the geometric relationships of the real world.

Translation Sensitivity

The MLP's Blindness

To an MLP, "Vector A" and "Vector B" look like completely different, unrelated inputs.

Because the inputs shifted to different positions in the array, the MLP uses entirely different sets of weights to process them.

Conclusion: An MLP must re-learn the concept of an "eye" independently for every single coordinate on the image! This is horribly inefficient.

2. The CNN Paradigm Shift

Convolutional Neural Networks (LeCun, 1989), inspired by the biological visual cortex of cats (Hubel & Wiesel), encode physical reality into the architecture using two Inductive Priors:

🔍 1. Locality (Sparse Connectivity)

We don't need to look at the whole image at once to find a vertical edge or a texture. We just need to look at a small, localized window (e.g., $3 \times 3$ pixels).

Solves Parameter Explosion: Instead of millions of weights, a neuron only has 9 weights!

🔄 2. Translation Invariance

A "cat" is still a "cat" whether it's in the top-left corner or the bottom-right corner. A feature detector useful in one place is useful everywhere.

Solves Spatial Sensitivity: Parameter Sharing means we slide the exact same weights across the entire image.

3. The Convolution Operation

A Filter (Kernel) is a small matrix of learnable weights (e.g., $3 \times 3$). We slide this filter over the input image to produce a 2D Activation Map.

At each sliding window position:

  1. Overlay: Match filter weights with image pixels.
  2. Multiply: Element-wise multiplication.
  3. Sum: Add all results together + a single Bias.
$$ S(i, j) = \sum_m \sum_n I(i+m, j+n) \cdot K(m, n) $$

4. Convolutions on 3D Volumes (RGB)

Real images have 3 color channels (Red, Green, Blue). How does the filter handle depth?

  • The filter is actually 3D! If the image has 3 channels, the filter must have a depth of 3 (e.g., $3 \times 3 \times 3$).
  • It computes the dot product across all spatial pixels AND all channels simultaneously, summing everything into a single scalar value.
  • Therefore, 1 Filter applied to an RGB image produces 1 Output Channel.

Multiple Filters

To find multiple features (e.g., horizontal edges, vertical edges, and curves), we use $N$ distinct filters. This generates an output volume with $N$ channels.

# in_channels=3 (RGB), out=64 filters
layer = nn.Conv2d(3, 64, kernel_size=3)

5. Spatial Control: Padding

Every time we apply a $3 \times 3$ convolution without padding, the image shrinks by 2 pixels on each side.

Why Pad?

  1. Preserve Resolution: Prevents the image from shrinking to nothing in deep networks.
  2. Edge Information: Without padding, corner pixels are only touched by the kernel once. Middle pixels are touched many times.

"Same" Padding: We surround the image with a border of Zeros to ensure Output Size = Input Size.

Zero Padding (P=1)

6. Stride & The Output Formula

Stride ($S$) is the "Step Size" of the sliding window.

  • Stride 1: Slide 1 pixel at a time. High overlap.
  • Stride 2: Slide 2 pixels. Skips information. Halves the spatial resolution.

Downsampling

Using Stride 2 is a common alternative to Pooling for aggressively reducing spatial dimensions and saving memory in modern CNNs.

The Universal Output Formula

Calculates the exact width/height of the next layer.

$$ O = \left\lfloor \frac{W - K + 2P}{S} \right\rfloor + 1 $$
W: Input Width | K: Kernel Size
P: Padding | S: Stride

7. The Receptive Field

If a kernel is only $3 \times 3$, how can the network ever recognize a huge object like a dog?

Hierarchical Expansion

By stacking multiple convolutional layers, the Receptive Field (the area of the original image that influences a specific activation) grows.

  • Layer 1 (3x3): A neuron "sees" a 3x3 patch of the image.
  • Layer 2 (3x3): A neuron looks at a 3x3 patch of Layer 1. Thus, it effectively "sees" a 5x5 patch of the original image!
  • Result: Deep in the network, a single $1 \times 1$ pixel contains semantic information about the entire original image.

8. Pooling Layers

Pooling heavily downsamples the spatial dimensions (H, W) independently for each channel.

Why Pool?

  1. Reduce Compute: Less memory and faster processing.
  2. Translation Invariance: Small shifts in the input pixel grid shouldn't change the classification.
Note: Pooling has no learnable weights!

Max Pooling vs Average Pooling

Max Pooling (taking the highest value in a 2x2 window) is the most common. It acts as an active "feature detector" (did an edge fire in this region?).

Summary

  • MLP Failure: Flattening images destroys spatial geometry and explodes the number of weights, guaranteeing OOM and overfitting.
  • CNN Priors: Based on Locality (sparse connections) and Translation Invariance (parameter sharing).
  • Convolution: Dot product between a sliding Kernel and the Image to extract features.
  • 3D Volumes: Kernels have the same depth as the input channels. Multiple filters create multiple output channels.
  • Padding: Preserves spatial dimensions (usually Zero-Padding).
  • Stride & Pooling: Aggressively downsample the image, increasing the Receptive Field for deeper layers.
