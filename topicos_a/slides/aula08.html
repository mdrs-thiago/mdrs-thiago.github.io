Batch, Layer, Instance & Group Norm

1. The Need for Normalization

Before deep diving into hidden layers, recall how we treat input data in standard Machine Learning: we Standardize it (Mean = 0, Variance = 1).

Why standardize inputs?

If Feature A ranges from $[0, 1]$ and Feature B ranges from $[0, 1000]$, the loss landscape becomes highly elongated (a ravine). The optimizer will struggle to find the minimum.

Internal Covariate Shift

In a deep network, even if inputs are normalized, the outputs of Layer 1 become the inputs to Layer 2. As weights update during training, the distribution of these hidden activations constantly shifts, slowing down convergence massively.

Loss Landscape: Unnormalized vs Normalized

2. Batch Normalization (Concept)

Proposed in 2015, BN solves Internal Covariate Shift by forcefully standardizing the activations inside the network, usually right before the activation function.

The Core Idea: We calculate the Mean ($\mu$) and Variance ($\sigma^2$) across the Batch dimension (N) for each individual feature channel.

$$\hat{x}_i = \frac{x_i - \mu_{\mathcal{B}}}{\sqrt{\sigma_{\mathcal{B}}^2 + \epsilon}}$$

Where $\epsilon$ (epsilon) is a tiny constant (e.g., $10^{-5}$) added for numerical stability to prevent division by zero.

Batch Norm: Learnable Parameters

Forcing the data to always have mean 0 and variance 1 might actually destroy useful representational power. The network must be allowed to "undo" the normalization if it needs to!

$$y_i = \gamma \hat{x}_i + \beta$$
  • $\gamma$ (Gamma): Learnable Scale (re-introduces variance).
  • $\beta$ (Beta): Learnable Shift (re-introduces mean).

During backpropagation, the optimizer learns the optimal $\gamma$ and $\beta$ for each channel. If the network decides that normalization is useless, it can simply learn $\gamma = \sigma$ and $\beta = \mu$ to restore the original tensor $x$.

PyTorch Usage

import torch.nn as nn

# Applied to a 2D feature map
# (e.g., after a Conv2d layer)
# Requires knowing the channel size
bn = nn.BatchNorm2d(num_features=64)

# Forward pass
out = bn(x)

Training vs. Inference (Crucial)

Batch Norm behaves completely differently depending on the phase of your project. This is a massive source of bugs in production.

During Training (model.train())

Calculates $\mu$ and $\sigma$ using the current mini-batch.

Simultaneously, it updates a Running Average of $\mu$ and $\sigma$ in the background (these are state variables, not gradients).

During Testing (model.eval())

At test time, you might process only 1 image at a time. The batch variance would be 0!

Therefore, BN stops calculating batch statistics and uses the Running Averages frozen from the training phase.

3. Beyond Batch Norm

What if we are working with high-resolution images or long sequences where we can only fit 1 or 2 samples per batch in GPU memory?

Layer Norm (LN)

Normalizes across the Channel (C) dimension for each single sample independently.

The absolute standard in NLP and Transformers. It does not care about the batch size at all.

# PyTorch Implementation
ln = nn.LayerNorm(normalized_shape=256)

Instance Norm (IN)

Normalizes the spatial dimensions (H, W) for each channel of each sample independently.

Used primarily in Style Transfer and GANs to remove contrast/style information from an image.

# PyTorch Implementation
in = nn.InstanceNorm2d(num_features=64)

Group Normalization (GN)

A smart middle ground. It divides the channels into $G$ groups and computes mean/variance within each group independently per sample.

The "Gold Standard" for Computer Vision when dealing with small batches (e.g., high-resolution Object Detection or Medical Image Segmentation).

Method Axis of Normalization Best Use Case
Batch Norm Across $(N, H, W)$ for each $C$ Standard CNNs (ResNet) with Large Batches
Layer Norm Across $(C, H, W)$ for each $N$ NLP, Transformers, RNNs
Instance Norm Across $(H, W)$ for each $N$ and $C$ Artistic Style Transfer, Image Generation
Group Norm Across $(Groups, H, W)$ for each $N$ Object Detection, Small Batch Vision

Question 3: Batch Norm Limits

Why does Batch Normalization fail catastrophically if your hardware only allows a batch_size = 1?

The variance is exactly 0, making normalization mathematically impossible.
The forward pass becomes too slow to compute.
It immediately causes the model to overfit the training data.
Reasoning: If you only have $1$ sample in the batch, that sample's value $x_i$ is exactly equal to the batch mean $\mu$. Thus, the numerator $x_i - \mu$ is always $0$, destroying all feature information. You need a batch of at least 2 (preferably much more) to compute meaningful statistics.

Summary

  • Internal Covariate Shift: Normalization helps smooth the loss landscape, enabling faster training and higher learning rates.
  • Batch Norm: Standardizes over the Batch. Essential for CNNs but requires model.train() / model.eval() awareness.
  • Layer Norm: Standardizes over Channels. Independent of batch size. The standard for Transformers/NLP.
  • Group Norm: The modern compromise for Computer Vision when memory limits force small batch sizes.
