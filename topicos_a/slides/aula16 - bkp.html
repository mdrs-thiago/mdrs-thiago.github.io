Section 1

Why NLP is Hard

The fundamental challenge of making computers understand language

1.1 — The Challenge of Language

Computers speak numbers. Humans speak ambiguity. The gap is enormous.

Ambiguity is Everywhere

  • "I saw the man with the telescope."
    Who has the telescope — me, or the man?
  • "Bank" — river bank or financial bank?
  • "She said she was happy." — sincere or sarcastic?

Why It Matters

Meaning depends on context, world knowledge, tone, and shared assumptions between speaker and listener. None of this is in the raw text.

2.2 — Tokenization

Tokenization splits text into discrete units the model will process. The granularity of splitting matters enormously.

Word Tokens

unhappiness

Split on spaces and punctuation.
Problem: huge vocabulary; "unhappy", "unhappily", "unhappiness" treated as totally unrelated.

Subword Tokens Modern

un happiness

Used by GPT, BERT (BPE, WordPiece). Balances vocabulary size and semantic overlap. Unknown words get split into known pieces.

Character Tokens

u n h a p p y

Tiny vocabulary (26 chars). Works for any language. Very long sequences — hard for models to learn long-range structure.

Byte-Pair Encoding (BPE) — How Subword Works

Start with characters, then iteratively merge the most frequent pair of adjacent tokens until a target vocabulary size is reached. "low", "lower", "lowest" share the subtoken low, capturing morphological similarity.

2.3 — Normalization & Python Code

Stemming vs. Lemmatization

Method Input Output
Stemming running runn
Stemming happily happili
Lemmatization running run
Lemmatization happily happy
Stemming is a heuristic cut — fast, but can produce non-words.
Lemmatization uses vocabulary + morphological analysis — slower, but linguistically correct.

Preprocessing with NLTK / spaCy

import nltk
from nltk.tokenize import word_tokenize
from nltk.corpus import stopwords
from nltk.stem import WordNetLemmatizer

text = "The dogs were running happily in the park."

# Tokenize + lowercase
tokens = word_tokenize(text.lower())

# Remove stop words
stops = set(stopwords.words('english'))
tokens = [t for t in tokens if t not in stops]

# Lemmatize
lemmer = WordNetLemmatizer()
lemmas = [lemmer.lemmatize(t, pos='v') for t in tokens]

# Result: ['dog', 'run', 'happily', 'park']
print(lemmas)

Section 3

Classical Representations

One-Hot · Bag of Words · TF-IDF

3.1 — One-Hot Encoding

The simplest possible representation: each word becomes a vector with a single 1 and all other positions set to 0.

Construction

Vocabulary: { cat, dog, fish, bird } — size V = 4

Problems

  • Orthogonality: Every word is equally distant from every other. cat and kitten are as different as cat and democracy.
  • Sparsity: For a vocab of V=50,000, each vector has 49,999 zeros.
  • No semantics: No notion of similarity, analogy, or meaning.
  • Out-of-vocabulary: New words → no representation.
Vector dimension = vocabulary size V
For 50,000 words: each vector has 49,999 zeros

3.2 — Bag of Words (BoW)

Instead of encoding one word, encode an entire document as a vector of word counts. Order is discarded — only frequency matters.

Example

Doc 1: "The cat sat on the mat"

Doc 2: "The dog sat on the rug"

Scikit-learn in Practice

from sklearn.feature_extraction.text import CountVectorizer

corpus = [
    "the cat sat on the mat",
    "the dog sat on the rug"
]

vec = CountVectorizer()
X = vec.fit_transform(corpus)

print(vec.get_feature_names_out())
# ['cat', 'dog', 'mat', 'on', 'rug', 'sat', 'the']
print(X.toarray())
# [[1, 0, 1, 1, 0, 1, 2],
#  [0, 1, 0, 1, 1, 1, 2]]
✅ Simple, interpretable, works well for many tasks.
⚠️ "the" scores high but carries no meaning. Word order lost.

3.3 — TF-IDF

BoW over-weights common words. TF-IDF penalises words that appear everywhere and rewards words that are distinctive to a document.

$$\text{TF-IDF}(t, d) = \underbrace{\frac{f_{t,d}}{\sum_k f_{k,d}}}_{\text{Term Frequency}} \times \underbrace{\log \frac{N}{1 + \text{df}(t)}}_{\text{Inverse Document Frequency}}$$

  • TF: How often does word t appear in document d? (normalised by doc length)
  • IDF: Across all N documents, how rare is word t? Rarer → higher weight.
  • Common words like "the", "and", "is" appear in all documents → IDF ≈ 0 → score ≈ 0.
  • Domain-specific terms like "photosynthesis" or "quaternion" score high.

Intuition

Corpus: 1,000 documents about cooking.

Word: "the" TF high, IDF ≈ 0 → score low
Word: "recipe" TF medium, IDF medium → moderate
Word: "soufflé" TF medium, IDF high → score high ✅ 
from sklearn.feature_extraction.text import TfidfVectorizer

tfidf = TfidfVectorizer()
X = tfidf.fit_transform(corpus)
# Each doc → dense meaningful vector

3.4 — The Representation Crisis

Classical methods enabled decades of useful NLP, but they hit a fundamental ceiling.

Problem Impact
Sparsity Vectors mostly zeros — memory and compute inefficient
No Semantics "car" and "automobile" treated as completely unrelated
Order Blindness "Dog bites man" = "Man bites dog" in BoW
Compositionality Meaning of phrases isn't sum of word meanings
OOV Words New words at inference → no representation

The Question We Need to Answer

Can we encode a word as a dense, low-dimensional vector where similar words are geometrically close to each other in vector space?

This is exactly what Word Embeddings achieve. →

Section 4

Word Embeddings

Word2Vec · GloVe · Semantic Space

4.1 — The Distributional Hypothesis

"You shall know a word by the company it keeps."

— J.R. Firth, 1957

Words that appear in similar contexts tend to have similar meanings. We can exploit this to learn vector representations from raw text without any labels.

From Counts to Geometry

If cat and dog both frequently appear next to pet, furry, vet, and feed, their learned vectors will be close in space — even though we never told the model what animals are.

Context Windows

Sentence: "The quick fox jumps over the fence"

Window size = 2:

quick The fox jumps over

Context words (red) co-occur with target word (blue).
These co-occurrences define the word's meaning.

4.2 — Word2Vec: CBOW & Skip-gram

Two shallow neural networks, trained to predict words from context (or context from words). The weight matrix is the embedding.

CBOW — Predict center from context

Skip-gram — Predict context from center

Skip-gram works better for rare words (each training example is a separate prediction). CBOW is faster and works better for frequent words. In practice, Skip-gram is more commonly used.

4.3 — Negative Sampling

Training a true softmax over a vocabulary of 50,000 words per step is computationally prohibitive. Negative Sampling is the key trick.

The Idea

Instead of predicting over the whole vocabulary, convert the task into a binary classification problem: "Is this pair (word, context) a real co-occurrence, or a random noise pair?"

$$\mathcal{L} = \log \sigma(\mathbf{v}_{w_O}^\top \mathbf{v}_{w_I}) + \sum_{k=1}^{K} \mathbb{E}_{w_k \sim P_n(w)} \left[ \log \sigma(-\mathbf{v}_{w_k}^\top \mathbf{v}_{w_I}) \right]$$

Training Process

1 Positive pair: ("fox", "quick") — they actually co-occur. Train to output probability ≈ 1.
2 Negative pairs: ("fox", "democracy"), ("fox", "Tuesday"), … — random samples from the corpus. Train to output probability ≈ 0.
3 Only K ≈ 5–20 negative samples per positive pair needed. Reduces computation by ~99%.
✓ After billions of such updates, the embedding matrix is the model — throw away everything else.

4.4 — Semantic Arithmetic & GloVe

Vector Arithmetic

Semantic relationships are encoded as geometric directions in vector space.

vec(king) − vec(man) + vec(woman) ≈ vec(queen)
vec(Paris) − vec(France) + vec(Italy) ≈ vec(Rome)
vec(swimming) − vec(swim) + vec(run) ≈ vec(running)
This works because the model learns relational dimensions: gender, geography, tense — as distinct geometric directions.

GloVe — Global Vectors

An alternative to Word2Vec (Pennington et al., 2014). Instead of a local context window, it factorises the global co-occurrence matrix.

$$J = \sum_{i,j=1}^{V} f(X_{ij}) \left( \mathbf{w}_i^\top \tilde{\mathbf{w}}_j + b_i + \tilde{b}_j - \log X_{ij} \right)^2$$
Word2Vec GloVe
Training Online (local windows) Batch (global matrix)
Speed Faster Slower (matrix build)
Quality Great on large corpora Often slightly better
Section 5

Recurrent Neural Networks

RNN · LSTM · GRU — Processing Sequential Data

5.1 — Why Sequences are Different

Feed-Forward Networks Fail Here

  • Fixed input size — text has variable length
  • Position-blind — word order not captured
  • No memory — can't relate "she" to "Alice" 10 words back
  • Parameter explosion — a new weight for each position

The RNN Solution

Process the sequence one token at a time, maintaining a hidden state $h_t$ — a running "memory" vector that gets updated at each step.

Key Properties We Need

🔁Parameter Sharing: Same weights applied at every time step — handles any sequence length
💾Memory: Hidden state carries information across time steps
📏Variable Length: Works on sentences of any length
🎯Causal: Output at step t depends only on inputs up to time t

5.2 — The RNN Architecture (Unrolled)

The Math

$$h_t = \tanh(W_h h_{t-1} + W_x x_t + b)$$ $$y_t = W_y h_t$$
  • $x_t$: Input at time step $t$ (word embedding)
  • $h_t$: Hidden state — the "memory" vector
  • $W_h, W_x$: Shared weights across all time steps
  • $y_t$: Output (e.g. class label, next word)

The same $W_h$ and $W_x$ are used at every time step — this is what enables variable-length input and efficient parameter use.

5.3 — The Vanishing Gradient Problem

The Fundamental Problem

During backpropagation, gradients are multiplied by $W_h$ at each time step. For long sequences (100+ steps), gradients either vanish to zero (||W||<1) or explode (||W||>1).

$$\frac{\partial \mathcal{L}}{\partial h_1} = \frac{\partial \mathcal{L}}{\partial h_T} \prod_{t=2}^{T} \frac{\partial h_t}{\partial h_{t-1}} = \frac{\partial \mathcal{L}}{\partial h_T} \cdot W_h^{T-1}$$

For T=100 and ||W||=0.9 → gradient ≈ 0.999 ≈ 0.000027. The model simply cannot learn long-range dependencies.

Effect on Learning

"The cat, which had been sleeping on the warm windowsill all afternoon, suddenly meowed."

An RNN processing this sentence will have essentially forgotten "cat" by the time it reaches "meowed". Long-range agreement and reference are nearly impossible to learn.

Solution: Gated Units

Replace the simple tanh cell with LSTM or GRU — units with explicit gating mechanisms that allow the network to choose what to remember and forget.

5.4 — LSTM: Long Short-Term Memory

Hochreiter & Schmidhuber (1997). Introduces a cell state $c_t$ — a "conveyor belt" for long-range memory, guarded by three learned gates.

The Three Gates

🔵 Forget Gate — $f_t = \sigma(W_f [h_{t-1}, x_t] + b_f)$
Decides what to erase from cell state. Output in [0, 1] per cell dimension.
🟢 Input Gate — $i_t = \sigma(...) \odot \tanh(...)$
Decides what new information to write into cell state.
🟡 Output Gate — $o_t = \sigma(W_o [h_{t-1}, x_t] + b_o)$
Decides what part of the cell state to expose as $h_t$.
Cell update: $c_t = f_t \odot c_{t-1} + i_t$
Gradients flow through + (addition), avoiding vanishing!

5.5 — GRU: Gated Recurrent Unit

Cho et al. (2014). A simpler alternative to LSTM — two gates instead of three, no separate cell state. Often matches LSTM performance at lower cost.

$z_t = \sigma(W_z [h_{t-1}, x_t])$ — Update gate

$r_t = \sigma(W_r [h_{t-1}, x_t])$ — Reset gate

$\tilde{h}_t = \tanh(W [r_t \odot h_{t-1}, x_t])$

$h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t$

LSTM vs. GRU vs. Vanilla RNN

Vanilla RNN GRU LSTM
Gates 0 2 3
Cell state No No Yes
Parameters Low Medium High
Handles long deps. Poor Good Very Good
Training speed Fast Medium Slower

In 2024, despite the Transformer's dominance, LSTMs and GRUs are still widely used in embedded systems, time series, and any low-latency application.

Section 6

Seq2Seq & Attention

The Encoder-Decoder Architecture and the Birth of Attention

6.1 — The Encoder-Decoder Architecture

Sutskever et al. (2014). For tasks where input and output are different-length sequences (e.g. translation, summarisation).

Encoder: Reads the full input sequence and compresses it into a fixed-size context vector $c = h_T$ (final hidden state).

Decoder: Generates output autoregressively — conditioned on the context vector and its own previous outputs.

6.2 — The Bottleneck & Attention

The Bottleneck Problem

Compressing an entire long document into a single fixed-size vector $c$ loses most information. Performance degrades sharply on long sequences — demonstrated clearly in machine translation by 2014.

Bahdanau Attention (2014)

Instead of using only the final hidden state, let the decoder look at ALL encoder hidden states at every decoding step, and learn which ones to focus on.

Attention Mechanism

$e_{ti} = \text{score}(s_{t-1}, h_i)$ — alignment score

$\alpha_{ti} = \dfrac{\exp(e_{ti})}{\sum_k \exp(e_{tk})}$ — softmax weights

$c_t = \sum_i \alpha_{ti} h_i$ — dynamic context vector

Section 7

The Transformer

"Attention is All You Need" — Vaswani et al., 2017

7.1 — Why Leave Recurrence Behind?

RNN Fundamental Limitations

  • Sequential bottleneck: Step $t$ requires step $t-1$ to finish. Cannot parallelise over the sequence length.
  • Long-range info decay: Even LSTMs struggle to keep information from 500 steps ago.
  • Training time: At 2017 scale, training on billions of tokens with RNNs was prohibitively slow.

The Transformer Solution

  • Pure attention: Replace recurrence entirely with self-attention.
  • Full parallelism: Every position attends to every other position simultaneously. GPU-friendly.
  • Constant path length: Any two positions are one attention step apart, regardless of distance.
Path length: RNN $O(n)$  →  Transformer $O(1)$
Training: Sequential  →  Fully Parallel

7.2 — Self-Attention: Query, Key, Value

Self-attention allows each position in a sequence to attend to every other position — capturing context without recurrence.

The Library Analogy

Think of a search engine:

  • Query (Q): What you're searching for — "what does it refer to?"
  • Key (K): The index of each position — "this is what I contain"
  • Value (V): The actual content to retrieve
$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

Dividing by $\sqrt{d_k}$ prevents dot products from growing too large, which would push softmax into saturation.

7.3 — Multi-Head Attention

Running a single attention function is like searching with only one query. Multi-head attention runs $h$ attention functions in parallel, each learning a different type of relationship.

$$\text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) W^O$$ $$\text{where head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$$
  • Each head uses its own projection matrices $W^Q_i, W^K_i, W^V_i$
  • Results concatenated and projected through $W^O$
  • GPT-3 uses 96 attention heads

What Different Heads Learn

Head A: Syntactic agreement
"The cats are…" (subject-verb)
Head B: Coreference
"it" → "animal"
Head C: Positional proximity
Short-distance relationships
Head D: Semantic roles
Subject, object, modifier relationships

7.4 — Positional Encoding

Attention is order-invariant: "dog bites man" and "man bites dog" produce the same attention matrix. We must inject position information explicitly.

Sinusoidal Encoding

$PE_{(pos, 2i)} = \sin\!\left(\dfrac{pos}{10000^{2i/d}}\right)$

$PE_{(pos, 2i+1)} = \cos\!\left(\dfrac{pos}{10000^{2i/d}}\right)$

  • Added directly to the input embeddings
  • Deterministic (no parameters to learn)
  • Different frequencies for each dimension — unique "fingerprint" per position
  • Generalises to sequences longer than training set

Visualising PE

7.5 — Full Transformer Architecture

Key Components

Self-Attention (Encoder):
Every input position attends to every other input position.
Masked Self-Attention (Decoder):
Prevents peeking at future tokens during training.
Cross-Attention (Decoder):
Decoder queries, Encoder keys & values — the Seq2Seq link.
Feed-Forward Network:
Two linear layers + ReLU, applied position-wise. "Processes" what attention collected.

Section 8

Pre-training & Fine-tuning

BERT · GPT · Transfer Learning for NLP

8.1 — Transfer Learning for NLP

Before 2018, NLP models were trained from scratch for every task. The Transformer enabled a new paradigm: pre-train once on massive unlabelled text, fine-tune cheaply on any task.

Two-Stage Paradigm

Stage 1 Pre-training: Train on terabytes of internet text (Wikipedia, books, web). Self-supervised — no labels needed. Weeks on thousands of GPUs.
Stage 2 Fine-tuning: Adapt to a specific task (sentiment, NER, Q&A) with a small labelled dataset. Hours on one GPU.

8.2 — BERT: Bidirectional Encoder

Devlin et al., Google (2018). Bidirectional Encoder Representations from Transformers. Uses the Transformer encoder only, pre-trained on two self-supervised tasks.

Task 1: Masked Language Modeling (MLM)

Input: "The [MASK] sat on the mat."
Target: predict cat for [MASK]
15% of tokens masked at random. Model must use both left and right context to predict — hence bidirectional.

Task 2: Next Sentence Prediction (NSP)

Input: [CLS] "Sentence A" [SEP] "Sentence B" [SEP]
Target: IsNext (True/False)?
Teaches the model about inter-sentence relationships.

BERT Key Properties

  • Bidirectional: Can see left AND right context simultaneously (GPT is left-to-right only)
  • Contextual embeddings: "bank" in "river bank" has a different vector than "bank" in "bank account"
  • BERT-base: 12 layers, 768 hidden dims, 12 heads, 110M parameters
  • BERT-large: 24 layers, 1024 dims, 16 heads, 340M parameters

Best for: Classification, NER, Q&A, anything that needs understanding context from both directions. Not for text generation.

8.3 — GPT: Causal Language Modeling

Radford et al., OpenAI (2018). Generative Pre-trained Transformer. Uses the Transformer decoder only, with a single pre-training task.

Causal Language Modeling (CLM)

Given: "The quick brown"
Predict: "fox"
Given: "The quick brown fox"
Predict: "jumps"
Autoregressive prediction — only looks at past tokens (masked self-attention). Trained on billions of tokens, one next-word at a time.
$$\mathcal{L} = \sum_{i} \log P(x_i \mid x_1, \ldots, x_{i-1}; \Theta)$$

The GPT Lineage

Model Year Parameters Key Innovation
GPT-1 2018 117M Pre-train + fine-tune
GPT-2 2019 1.5B Zero-shot via scaling
GPT-3 2020 175B Few-shot prompting
InstructGPT 2022 175B RLHF alignment
GPT-4 2023 >1T? Multimodal, reasoning

Best for: Text generation, summarisation, code, conversational AI, few-shot learning. Foundation of the current LLM era.

Section 9

Large Language Models

Scaling Laws · Emergent Abilities · RLHF · Prompting

9.1 — Scaling Laws

Kaplan et al., OpenAI (2020). Model performance follows power-law relationships with model size, data size, and compute — predictably.

$$\mathcal{L}(N) \propto N^{-\alpha}$$

Loss decreases as a smooth power law of parameters $N$, tokens $D$, and compute $C$.

Chinchilla Scaling (2022)

DeepMind found GPT-3 was undertrained. Optimal ratio: ~20 tokens per parameter. A 70B model needs ~1.4T training tokens for peak efficiency.

Parameters vs. Capability (log scale)

9.2 — Emergent Abilities & Few-Shot Learning

Emergent Abilities

Abilities that appear unpredictably at scale — absent in small models, sudden in large ones. Multi-step arithmetic, code debugging, analogical reasoning — these were not explicitly trained.

Zero-shot: "Translate to French: 'Hello'" → responds correctly with no examples

Few-shot: Given 3-5 examples in the prompt → generalises to new inputs

Prompting Strategies

Zero-shot:
"Is this review positive or negative? 'The food was terrible.'"
Few-shot:
"Positive: 'Great product!' → 😊
Negative: 'Broke in a week.' → 😠
? 'Pretty good overall.' → "
Chain-of-Thought (Wei et al., 2022):
"Let's think step by step…" → dramatically improves multi-step reasoning

9.3 — RLHF: Aligning LLMs to Human Values

A raw language model predicts the next token — it has no concept of being helpful, honest, or safe. RLHF (Christiano et al., 2017; InstructGPT, 2022) changes this.

1️⃣
Supervised Fine-Tuning (SFT)
Human labelers write ideal responses. Model fine-tuned on this curated dataset.
▶
2️⃣
Reward Model Training
Show human two responses. Ask: which is better? Train a Reward Model on these preferences.
▶
3️⃣
RL Optimization (PPO)
Use Proximal Policy Optimization to fine-tune LLM to maximise reward, with a KL constraint to prevent drift.

What RLHF Achieves

  • Follows instructions reliably
  • Safer, less toxic outputs
  • More helpful and concise answers

Open Challenges

  • "Reward hacking" — gaming the reward model
  • Expensive human labeling
  • Values depend on who you ask

Open Problems in LLMs

⚠ Hallucination: Models generate fluent but false content with high confidence.
⚠ Context length: Performance degrades on very long documents ("lost in the middle").
⚠ Reasoning: Still brittle on complex multi-step logical/math reasoning without CoT.
⚠ Interpretability: We still don't know exactly what these models learn internally.
→ Active research: RAG, tool use, agents, Constitutional AI, sparse attention, quantisation.

Summary: The NLP Journey

Sect. 1–2 NLP Fundamentals: Language is ambiguous. Preprocessing (tokenization, lemmatization, stop words) converts raw text into structured tokens.
Sect. 3 Classical Representations: One-Hot, Bag of Words, TF-IDF map text to numbers — but suffer from sparsity, no semantic meaning, and lost word order.
Sect. 4 Word Embeddings: Word2Vec and GloVe learn dense semantic vectors from the distributional hypothesis. Semantic arithmetic emerges naturally.
Sect. 5 RNNs / LSTM / GRU: Handle variable-length sequences with shared weights. LSTM gates solve the vanishing gradient problem for long-range memory.
Sect. 6 Seq2Seq & Attention: The encoder-decoder architecture handles I/O of different lengths. Bahdanau attention eliminates the context-vector bottleneck.
Sect. 7 The Transformer: Self-attention (Q, K, V) replaces recurrence. Multi-head attention captures multiple relation types. Fully parallelisable — changed everything.
Sect. 8 BERT & GPT: Pre-train on massive unlabelled text, fine-tune cheaply. BERT = bidirectional understanding; GPT = autoregressive generation.
Sect. 9 LLMs: Scaling laws + emergent abilities + RLHF = GPT-4, Claude, Gemini. Remain powerful but imperfect — hallucination and alignment are open problems.
