Model Diagnostics

Learning Curves, Confusion Matrices, and Error Analysis

Thiago Medeiros

Universidade do Estado do Rio de Janeiro

1. The Core Question

When a model's performance is disappointing, guessing architectures randomly is a terrible strategy. We must answer systematically:

  • Is the model underfitting or overfitting? (Optimization problem)
  • Is the data the problem? (Label noise, class imbalance, dataset shift)
  • Which errors matter most? (E.g., confusing a car with a truck vs. a car with a pedestrian)
  • What is the next best experiment to run?
The Engineer's Rule: No new architecture, hyperparameter, or loss function should be added until you can explain your current errors.

The Diagnostic Loop (Practical)

1) Measure

  • Track Learning Curves (Loss / Metric).
  • Compute the Confusion Matrix.
  • Extract Per-Class metrics (Precision, Recall).

2) Explain

  • Collect actual failure examples.
  • Cluster the errors into specific modes (e.g., "Fails in low light").
  • Formulate a hypothesis for a targeted fix.

3) Act (The Cheat Sheet)

Symptom Likely Cause First Fix
Train ↓, Val ↑ Overfitting Augmentation / Weight Decay / Early Stop
Both Train/Val High Underfitting Bigger Model / Higher LR / Train longer
Only one class fails Imbalance Reweight loss / Resample / More data
Confident & Wrong Data Leak / Noise Sanity check pipeline / Clean labels

2. Learning Curves

Plotting Train vs Validation loss across epochs is your primary window into the optimization process.

What to look for:

  • The Gap: The distance between train and val tells you the generalization capability.
  • Plateaus: Model stopped learning. Might need a Learning Rate Schedule (e.g., StepLR).
  • Noisy Val Curve: Validation set is too small, or batch size is tiny.

Minimal Logging: Always log Train Loss, Val Loss, Epoch Time, Learning Rate, and Seed.

Reading Curves: Capacity vs. Data

A common mistake is gathering more data when the model actually needs more capacity.

High Train Loss + High Val Loss

The curves are close to each other, but the error is unacceptably high.

Diagnosis: High Bias (Underfitting).

Adding more data will NOT help.

The model is too weak to capture the patterns. You need a deeper network (more layers/neurons) or a better architecture.

Low Train Loss + High Val Loss

The train curve drops to zero, but the validation curve is stuck high up.

Diagnosis: High Variance (Overfitting).

Adding more data is the BEST solution.

If you can't get more data, apply aggressive Regularization (Dropout, Weight Decay, Augmentation).

PyTorch: Logging Curves (Minimal)

You don't always need complex dashboards (like Weights & Biases) to do basic diagnostics.

3. The Confusion Matrix

A class-by-class breakdown: what gets confused with what.

  • Reveals systematic failure modes.
  • Separates "hard pairs" (Cat vs Dog) from random noise.
  • Crucial for highly imbalanced datasets.

Hover over the cells to see the exact values. Darker blue = higher concentration.

Evaluating Mistakes Visually

Not all errors have the same weight in real-world applications. The Confusion Matrix helps you identify the severity of the model's blindness.

Hierarchical Mistakes (Expected)

The model confuses a Husky with an Alaskan Malamute.

This indicates the model has learned the concept of "Dog", but lacks fine-grained capacity. Often acceptable or easily fixable with longer training/fine-tuning.

Catastrophic Mistakes (Dangerous)

The model confuses a Husky with a Truck.

This indicates a complete failure in feature representation. Usually points to a bug in the data pipeline, corrupted labels, or severe data leakage.

Code: Building a Confusion Matrix

import torch

def confusion_matrix(y_true, y_pred, num_classes):
    # y_true, y_pred: tensores 1D (N,)
    cm = torch.zeros((num_classes, num_classes), dtype=torch.int64)
    
    # Preencher a matriz
    for t, p in zip(y_true, y_pred):
        cm[t, p] += 1
        
    return cm

# Precisão, Recall e F1 por classe
tp = cm.diag()
support = cm.sum(dim=1)  # Verdadeiros
pred_sum = cm.sum(dim=0) # Previstos

# Usar clamp(min=1) para evitar divisão por 0
precision = tp / pred_sum.clamp(min=1)
recall = tp / support.clamp(min=1)

f1 = 2 * (precision * recall) / (
    precision + recall).clamp(min=1e-8)

Preste muita atenção ao support: classes muito raras podem inflacionar a variância das métricas.

4. Error Analysis & Slicing

Turn metrics into insight by manually inspecting examples. Deep learning requires you to look at your data!

The Inspection Workflow

  1. Collect wrong predictions + confidences.
  2. Sort by Highest Confidence Wrong.
  3. Group into Error Modes (e.g., Blurry, Occluded).
  4. Write a hypothesis for each group.
  5. Pick the cheapest intervention (e.g., Augmentation vs new labels).

Slicing the Data

Don't just look at global accuracy. Calculate metrics for specific subgroups:

  • By Lighting (Day vs Night)
  • By Demographics (Fairness/Bias)
  • By Object Size (Small vs Large Bounding Boxes)

The "Confident Wrong" quadrant is where you find Label Noise (dataset bugs) and Spurious Correlations (shortcut learning).

Actionable Fixes: Cheat Sheet

Once you identify the Error Mode, apply the correct intervention.

Observed Failure Mode Likely Cause Intervention (Fix)
Confuses two very similar classes Boundary ambiguity / Lack of capacity Collect more fine-grained data, Focal Loss, Deeper Model.
Consistently fails on a rare class Class Imbalance Reweighting (WeightedRandomSampler), Augmentation.
Fails under specific lighting/blur Domain Shift Apply ColorJitter/Blur augmentations during train to match test.
High confidence wrong (e.g. watermark) Shortcut Learning Data diversification, crop out watermarks, heavy regularization.

Code: Fixing Imbalance (Weighted Sampling)

Instead of showing the network 99 background images for every 1 tumor image, we force the DataLoader to sample them 50/50.

from torch.utils.data import DataLoader, WeightedRandomSampler
import torch

# Assumindo que tens as etiquetas para todo o dataset de treino: train_targets (N,)
class_counts = torch.bincount(train_targets)

# Inverso da frequência: classes raras recebem peso maior
class_weights = 1.0 / class_counts.float()

# Atribuir o peso correspondente a cada amostra individual
sample_weights = class_weights[train_targets]

# Criar o amostrador (Replacement=True é obrigatório para oversampling)
sampler = WeightedRandomSampler(
    weights=sample_weights.double(),
    num_samples=len(sample_weights),
    replacement=True
)

# Passar o sampler para o DataLoader (não usar shuffle=True neste caso)
train_loader = DataLoader(train_ds, batch_size=64, sampler=sampler)

Summary

  • Learning curves diagnose Underfitting (Capacity needed) vs Overfitting (Data/Regularization needed).
  • Confusion matrices show where errors concentrate across specific class interactions.
  • Error analysis converts raw numbers into hypotheses by forcing you to look at the data (especially Confident Errors).
  • Good, systematic diagnostics always beat random architecture changes or blind hyperparameter tuning.
