Learning Curves, Confusion Matrices, and Error Analysis

0. The Core Question

When performance is disappointing, we want to answer:

  • Is the model underfitting or overfitting?
  • Is the data the problem? (label noise, imbalance, dataset shift)
  • Which errors matter? (which classes, which failure modes)
  • What is the next best experiment?
Rule of thumb: No new architecture until you can explain current errors.

Diagnostic Loop (Practical)

1) Measure

  • Learning curves
  • Confusion matrix
  • Per-class metrics

2) Explain

  • Collect failures
  • Cluster error modes
  • Hypothesis → targeted fix

3) Act

SymptomLikely CauseFirst Fix
Train ↓, Val ↑OverfittingAugment / regularize
Train highUnderfittingCapacity / LR / train longer
One class failsImbalance / label driftReweight / sample / data
Confident wrongCalibration / shiftTemp scaling / data checks

1. Learning Curves

Plot train vs validation across epochs: loss + accuracy.

What to look for

  • Gap between train/val (generalization)
  • Plateau (optimization / LR schedule)
  • Noisy val (small val set / randomness)
  • Divergence (bug, label mismatch, data leak)
Minimal logging: loss, accuracy, LR, epoch time, seed, git hash.

In the lab, replace synthetic curves with your own logs.

Reading Curves: Typical Patterns

PatternInterpretationTry First
Train improves; Val gets worse Overfitting Augmentation, weight decay, early stop
Both bad + flat Underfitting or LR too small Bigger model, higher LR, longer training
Val oscillates wildly Small val / high variance Bigger val, k-fold, set seeds
Sudden spikes Data pipeline / augmentation bug Sanity-check batches; deterministic run

PyTorch: Logging Curves (Minimal)

# inside your training script
history = {"train_loss": [], "val_loss": [], "train_acc": [], "val_acc": []}

for epoch in range(epochs):
    train_loss, train_acc = train_one_epoch(...)
    val_loss, val_acc = evaluate(...)

    history["train_loss"].append(train_loss)
    history["val_loss"].append(val_loss)
    history["train_acc"].append(train_acc)
    history["val_acc"].append(val_acc)

# later: save to json for reproducibility
import json, pathlib
pathlib.Path("runs").mkdir(exist_ok=True)
with open("runs/history.json", "w") as f:
    json.dump(history, f, indent=2)

If you already use TensorBoard/W&B, keep the JSON anyway (portable artifact).

2. Confusion Matrix

A class-by-class breakdown: what gets confused with what.

Why it matters

  • Reveals systematic failure modes.
  • Separates "hard pairs" (cat vs dog) from random noise.
  • Guides targeted data collection or augmentation.
Tip: Always show both raw counts and row-normalized (% by true class).

Hover cells to see values. Darker = larger error mass.

PyTorch: Building a Confusion Matrix

import torch

def confusion_matrix(y_true, y_pred, num_classes: int):
    # y_true, y_pred: (N,) int64
    cm = torch.zeros((num_classes, num_classes), dtype=torch.int64)
    for t, p in zip(y_true, y_pred):
        cm[t, p] += 1
    return cm

# Example usage after eval loop:
all_true = torch.cat(true_labels)   # shape (N,)
all_pred = torch.cat(pred_labels)   # shape (N,)
cm = confusion_matrix(all_true, all_pred, num_classes=C)

Per-class metrics

# Precision/Recall/F1 per class from cm
tp = cm.diag()
support = cm.sum(dim=1)  # per true class
pred_sum = cm.sum(dim=0) # per predicted class

precision = tp / (pred_sum.clamp(min=1))
recall = tp / (support.clamp(min=1))
f1 = 2 * (precision * recall) / (precision + recall).clamp(min=1e-12)

Pay attention to support (rare classes inflate variance).

Common Pitfalls

  • Label mapping mismatch (class indices swapped) → diagonal looks bad everywhere.
  • Imbalanced test set → overall accuracy hides minority collapse.
  • Data leakage → suspiciously perfect diagonal.
  • Multi-label vs multi-class → confusion matrix is the wrong tool if multiple labels per sample.
Sanity checks: visualize 16 random samples + labels; verify class-to-name dictionary.

3. Error Analysis

Turn metrics into insight by inspecting examples.

Workflow

  1. Collect wrong predictions + confidences.
  2. Sort by highest confidence wrong.
  3. Group into error modes.
  4. Write a hypothesis for each group.
  5. Pick the cheapest intervention.
Gold: a small spreadsheet with image/text, true, pred, confidence, notes.

Typical error modes (CV)

  • Occlusion / small objects
  • Background bias (spurious cues)
  • Lighting / blur
  • Label noise / ambiguous class boundary

Typical error modes (NLP)

  • Negation, sarcasm
  • OOV / domain shift
  • Long context truncation

Top Confident Errors

“Confident wrong” is where you often find:

  • Label noise (dataset issue)
  • Spurious correlations (shortcut learning)
  • Calibration problems
# during evaluation (classification)
probs = logits.softmax(dim=1)           # (B, C)
conf, pred = probs.max(dim=1)           # (B,)
wrong = pred.ne(y_true)

# keep examples where model is wrong but very confident
mask = wrong & (conf >= 0.90)
hard_ids = batch_ids[mask]
hard_conf = conf[mask]
hard_pred = pred[mask]
hard_true = y_true[mask]

Then dump to CSV/JSON with file paths (CV) or raw text (NLP) for inspection.

Actionable Fixes: a Cheat Sheet

Observed failureLikely causeIntervention
Confuses two similar classesBoundary ambiguityMore data, better labels, focal loss
Fails on rare classImbalanceReweighting, sampling, augmentation
Fails under lighting/blurDomain shiftAugment to match test conditions
High confidence wrongShortcut learningData diversification, regularize, explainability

Lab: Diagnostics on Your CNN

Goal: produce a short diagnostics report + patch one failure mode.

Deliverables (today)

  • Train/val curves (loss + accuracy)
  • Confusion matrix (counts + normalized)
  • Top-20 confident errors (with notes)
  • One targeted change + re-run

Targeted changes (pick 1)

  • Strong augmentation (RandAugment/ColorJitter)
  • Class reweighting or WeightedRandomSampler
  • Label smoothing
  • Early stopping + best checkpoint
Constraint: keep it measurable. One change, one hypothesis.

Starter: Weighted Sampling (Imbalance)

from torch.utils.data import DataLoader, WeightedRandomSampler
import torch

# assume you have labels for each sample in train set: train_targets (N,)
class_counts = torch.bincount(train_targets)
class_weights = 1.0 / class_counts.clamp(min=1)

sample_weights = class_weights[train_targets]  # (N,)
sampler = WeightedRandomSampler(
    weights=sample_weights.double(),
    num_samples=len(sample_weights),
    replacement=True
)

train_loader = DataLoader(train_ds, batch_size=64, sampler=sampler, num_workers=2)

Pair this with per-class metrics to validate the effect.

Summary

  • Learning curves diagnose under/overfitting + optimization issues.
  • Confusion matrices show where errors concentrate across classes.
  • Error analysis converts numbers into hypotheses and targeted fixes.
  • Good diagnostics beats random architecture changes.
