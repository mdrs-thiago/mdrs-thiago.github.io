What is Deep Learning?

The paradigm shift from Feature Engineering to Representation Learning.

Traditional ML

  • Requires domain experts to hand-craft features (e.g., edge detectors, SIFT, TF-IDF).
  • Model only learns the mapping from features to outputs.
  • Performance plateaus relatively quickly, even if you add more data.

Deep Learning

  • End-to-end learning: raw data goes in, predictions come out.
  • The network automatically discovers the optimal hierarchical representations.
  • Scales incredibly well with massive datasets and compute.

  • 2016: AlphaGo - Reinforcement Learning defeats the world champion in Go.

The Underlying Truth

Despite these massive breakthroughs, the foundational mathematics (Calculus, Linear Algebra, and Gradient Descent) remain largely the same as they were in 1986. Only the architectures, data, and compute scaled up.

Deep Learning Frameworks

We need software that provides Automatic Differentiation and GPU acceleration out of the box.

Feature PyTorch (Meta) TensorFlow (Google)
Paradigm Dynamic Computation Graph (Eager) Static Graph (Historically) *
Usability Pythonic, feels like NumPy. Easy to debug using standard Python tools. Steeper learning curve. Debugging can be cryptic inside `tf.function`.
Adoption Dominant in Research (>80% of NeurIPS/CVPR papers). Declining in academia, but still strong in legacy codebases.

The Fundamental Unit: Tensors

A Tensor is a generalization of scalars, vectors, and matrices to $n$-dimensions. They are the core data structure in deep learning.

  • Scalar (0-D): $x \in \mathbb{R}$ (e.g., Loss value)
  • Vector (1-D): $v \in \mathbb{R}^n$ (e.g., Biases)
  • Matrix (2-D): $M \in \mathbb{R}^{n \times m}$ (e.g., Grayscale Image, Weights)
  • Tensor (3-D): $T \in \mathbb{R}^{c \times h \times w}$ (e.g., RGB Image)
  • Tensor (4-D): $T \in \mathbb{R}^{b \times c \times h \times w}$ (e.g., A batch of RGB images)
import torch

# Creating a 4D Tensor (Batch, Channels, Height, Width)
x = torch.randn(32, 3, 224, 224) 

print(x.dim())
# 4

The Anatomy of a PyTorch Tensor

Every tensor has three critical properties that you must track to avoid bugs.

1. Shape

The size of each dimension.

x.shape 
# torch.Size([3, 224, 224])

Most DL bugs are shape mismatch errors during matrix multiplication.

2. Dtype

Data type (float, int, etc).

x.dtype 
# torch.float32

NN weights default to `float32`. Using `float64` wastes 2x VRAM with no accuracy gain.

3. Device

Where memory is allocated.

x.device 
# device(type='cpu')

Operations between a CPU tensor and a GPU tensor will crash immediately.

Operations & Broadcasting

PyTorch syntax is deeply inspired by NumPy. The most critical operations are reshaping and matrix multiplications.

Matrix Multiplication

The backbone of neural network layers.

W = torch.randn(10, 5) # Weights
x = torch.randn(5, 1)  # Input

# Matrix Multiplication (Dot Product)
y1 = torch.matmul(W, x)
y2 = W @ x  # Syntactic sugar

print(y2.shape) # torch.Size([10, 1])

Broadcasting

Automatically expands smaller tensors to match larger ones during operations.

matrix = torch.ones(3, 3)
vector = torch.tensor([1, 2, 3])

# Vector is "broadcasted" across 
# all rows of the matrix
result = matrix + vector

""" Result:
tensor([[2., 3., 4.],
        [2., 3., 4.],
        [2., 3., 4.]])
"""

The Real Magic: Autograd

PyTorch isn't just NumPy on GPUs. It contains an Automatic Differentiation engine that records a computational graph on the fly.

  • Setting requires_grad=True tells PyTorch to track all operations applied to this tensor.
  • Calling .backward() traverses the graph backwards, applying the Chain Rule (Calculus) automatically.
  • The resulting gradients are stored in the .grad attribute.
# f(x) = x^2 + 5x
x = torch.tensor([2.0], requires_grad=True)

y = x**2 + 5*x

# Calculate derivative dy/dx
y.backward()

# Evaluated at x=2: 2(2) + 5 = 9
print(x.grad) 
# tensor([9.])

Why GPUs? (CUDA Acceleration)

Deep Learning boils down to massive amounts of matrix multiplications. CPUs are optimized for sequential logic; GPUs are designed for massive parallelism.

The Golden Rule: Operations can only be performed on tensors residing on the same device. A CPU tensor cannot be multiplied by a GPU tensor. 
# 1. Check if an NVIDIA GPU is available
if torch.cuda.is_available():
    device = torch.device("cuda") # or "mps" for Apple Silicon
else:
    device = torch.device("cpu")

# 2. Move tensors to the device memory
x = torch.randn(1000, 1000).to(device)
y = torch.randn(1000, 1000).to(device)

# 3. This operation now executes highly parallelized on the GPU
z = x @ y
