2. The Bounding Box & Output Vector

To localize an object, the Neural Network must predict a set of continuous numbers (a Regression task).

Coordinates Formulation

  • $x_c, y_c$: The Center of the box (relative to the grid).
  • $w, h$: The Width and Height (relative to the whole image).
  • $p_c$: Confidence score (Probability that an object exists in this box).
  • $c_1 \dots c_n$: Probability distribution over the classes (e.g., Cat, Dog, Car).

The Prediction Vector

$\mathbf{\hat{y}} = [p_c, \ x_c, \ y_c, \ w, \ h, \ c_1, \dots, c_n]$

If we are predicting across 20 possible classes, every single bounding box prediction is a vector of size 25.

3. Intersection over Union (IoU)

How do we measure if a predicted bounding box is "correct" compared to the Ground Truth human label?

$$ IoU = \frac{\text{Area of Intersection}}{\text{Area of Union}} $$
  • $IoU = 1.0$: Perfect overlapping match.
  • $IoU \ge 0.5$: Traditionally considered a "True Positive" detection.
  • $IoU < 0.5$: Considered a "False Positive" (bad localization).

Code: Computing IoU in PyTorch

A classic computer vision engineering task. Boxes are usually in format [x1, y1, x2, y2].

import torch

def calcular_iou(box1, box2):
    # 1. Encontrar as coordenadas do retângulo de interseção
    x1 = torch.max(box1[0], box2[0])
    y1 = torch.max(box1[1], box2[1])
    x2 = torch.min(box1[2], box2[2])
    y2 = torch.min(box1[3], box2[3])

    # 2. Calcular a Área de Interseção (clamp evita valores negativos)
    inter_area = torch.clamp(x2 - x1, min=0) * torch.clamp(y2 - y1, min=0)

    # 3. Calcular a Área de União (Área1 + Área2 - Interseção)
    box1_area = (box1[2] - box1[0]) * (box1[3] - box1[1])
    box2_area = (box2[2] - box2[0]) * (box2[3] - box2[1])
    union_area = box1_area + box2_area - inter_area

    # 4. Retornar o rácio (Adicionar epsilon para evitar divisão por zero)
    return inter_area / (union_area + 1e-6)

4. Evaluation: mAP

How do we evaluate the model on the entire dataset? We use Mean Average Precision (mAP).

  • Average Precision (AP): The area under the Precision-Recall curve for a single class (e.g., Cars).
  • Mean AP (mAP): The average of the AP scores across all classes.

mAP@0.5 vs mAP@0.5:0.95

mAP@0.5 considers any box with IoU > 0.5 as a hit.

mAP@0.5:0.95 (COCO Standard) averages the mAP across multiple strict IoU thresholds. It demands extremely precise box outlines.

5. The YOLO Paradigm

Two-Stage Detectors (Old Way)

Algorithms like Faster R-CNN first generated thousands of "region proposals" (Phase 1) and then ran a CNN classifier on every single proposal (Phase 2).

Highly accurate, but terribly slow (not real-time).

YOLO (You Only Look Once)

Reframes detection as a single regression problem.

A single CNN looks at the whole image and simultaneously outputs multiple bounding box coordinates and class probabilities in a single forward pass.

Extremely fast (Real-Time Video).

The Grid Mechanism

YOLO divides the input image into an $S \times S$ grid (originally $7 \times 7$).

S x S Grid

The Golden Rule

If the center of an object falls into a specific grid cell, ONLY that cell is responsible for detecting that object.

The Tensor Output

The final layer of YOLO is a $1 \times 1$ Convolution that outputs a massive 3D Tensor of shape:

$\mathbf{S \times S \times [B \cdot (5 + C)]}$

(Where $B$ = Number of boxes per cell, $C$ = Number of Classes)

6. Anchor Boxes (Priors)

It is mathematically unstable for the network to guess arbitrary bounding box widths and heights from scratch. Instead, we provide templates.

  • Anchors are pre-defined box shapes (e.g., Tall, Wide, Square) clustered from the dataset.
  • The network doesn't predict $W$ and $H$ directly. It predicts offsets (scaling factors) to apply to these anchor templates.

Over-prediction Strategy

If $S=13$ and $B=3$ anchors, the model outputs $13 \times 13 \times 3 = \mathbf{507}$ boxes every time! Most will have $p_c \approx 0$ (background) and will be ignored.

Cell with 3 Anchors

7. The Multi-Part Loss Function

Training YOLO is complex because we must optimize Regression (coordinates) and Classification (labels) simultaneously.

$$ \mathcal{L} = \lambda_{coord} \sum (\text{xywh Errors}) \ + \sum (\text{Objectness Error}) \ + \lambda_{noobj} \sum (\text{No-Object Error}) \ + \sum (\text{Class Error}) $$

1. Localization (xywh)

Usually Mean Squared Error (MSE). We often penalize errors in small boxes more than large boxes (using square roots).

2. The Imbalance Problem ($\lambda_{noobj}$)

Most of the 507 boxes contain only background. If we treat all boxes equally, the "No-Object" gradients will overpower the rare "Object" gradients.

We use $\lambda_{noobj} = 0.5$ to down-weight background errors.

8. Cleaning Predictions (NMS)

YOLO will often predict multiple boxes for the exact same object (from adjacent grid cells). We clean this up using Non-Maximum Suppression.

  1. Discard all boxes with Confidence Score $p_c < \text{threshold}$ (e.g., $0.5$).
  2. Pick the box with the highest score (the Maximum).
  3. Compute the IoU of this box with all other boxes for the same class.
  4. Suppress (delete) any box that has an $IoU > 0.4$ with the Maximum box.
  5. Repeat step 2 for the remaining boxes.

Summary & Next Steps

  • Detection vs Classification: Detection requires outputting multiple continuous bounding box vectors per image.
  • IoU & mAP: Intersection over Union measures individual box accuracy; mAP evaluates the entire detection model.
  • The YOLO Grid: Divides the image into $S \times S$ cells, where each cell predicts $B$ Anchor Boxes.
  • The Loss Function: Balances Regression (coordinates) with Classification, severely penalizing the background class to avoid collapse.
  • NMS: A post-processing algorithm to clean up overlapping, redundant predictions.
