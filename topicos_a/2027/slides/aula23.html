Prompt é código: versione, teste com um conjunto de exemplos e meça antes de mudar.

O LLM não conhece seus documentos (privados, recentes, específicos) e alucina quando não sabe. Solução: buscar os trechos relevantes e colocá-los no prompt.

  • Conhecimento atualizável sem retreinar: é só reindexar
  • Respostas citáveis: dá para mostrar a fonte
  • Controle de acesso: busque só o que o usuário pode ver
  • Chunking: pedaços de ~300–800 tokens com sobreposição; respeite a estrutura (seções, parágrafos)
  • Embeddings de sentença: um encoder (ex.: sentence-transformers, multilíngue) treinado para que perguntas e respostas fiquem próximas
  • Índice vetorial: FAISS, Chroma, pgvector. Busca aproximada em milhões de vetores
  • Busca híbrida: vetorial + BM25 (palavras exatas, siglas, códigos)
  • Reranking: um cross-encoder reordena os top-20 → top-5
from sentence_transformers import SentenceTransformer

               normalize_embeddings=True)

Falhas típicas

  • Retrieval: o trecho certo não veio (chunk mal cortado, sigla, pergunta vaga)
  • Geração: o trecho veio, mas o LLM ignorou ou misturou com o que "sabe"
  • Contexto demais: muitos chunks irrelevantes confundem
  • Prompt injection: um documento com "ignore as instruções anteriores..."

Avalie as duas partes separadamente

  • Retrieval: o chunk com a resposta está no top-k? (recall@k)
  • Fidelidade: a resposta é sustentada pelos chunks?
  • Relevância: a resposta responde à pergunta?
  • Conjunto de teste com perguntas e respostas conhecidas: é o seu benchmark

LoRA (Hu et al., 2022)

$\mathbf{W}' = \mathbf{W} + \Delta\mathbf{W} = \mathbf{W} + \mathbf{B}\mathbf{A}$
  • $\mathbf{W} \in \mathbb{R}^{d \times d}$ congelada; $\mathbf{B} \in \mathbb{R}^{d \times r}$, $\mathbf{A} \in \mathbb{R}^{r \times d}$ treináveis, com $r$ = 8–64
  • Para $d = 4096$, $r = 16$: $2 \cdot 4096 \cdot 16 = 131$ mil vs. 16,8 milhões parâmetros (0,8%)
  • Hipótese: a adaptação tem baixo posto
  • Adaptadores pequenos (MBs): um por cliente/tarefa, mesmo modelo base

Quantização e QLoRA

  • Pesos em 8 ou 4 bits em vez de 16 → 2–4× menos memória
  • QLoRA (Dettmers et al., 2023): base quantizada em 4 bits + LoRA → fine-tuning de modelo de 7–8 B numa única GPU de ~16 GB
  • Para inferência local: formatos GGUF (llama.cpp, Ollama)

Regra prática: comece por prompting → adicione RAG se faltar conhecimento → faça fine-tuning se faltar comportamento ou se precisar de um modelo menor e mais barato. Combinações são comuns.

Agentes (visão geral)

LLM em loop com ferramentas: buscar na web, rodar código, chamar APIs. Padrão ReAct: pensar → agir → observar → repetir.

Riscos: ações irreversíveis, custo que explode, injeção de instruções por conteúdo externo. Sempre com limites e supervisão humana.

Ética e custo

  • Viés: herdado dos dados (Aula 13), amplificado em escala
  • Privacidade: o que você envia para uma API? Dados pessoais e LGPD
  • Direitos autorais nos dados de treino
  • Energia e água: treino e inferência têm pegada real (Bender et al., 2021; Luccioni et al., 2024)
  • Responsabilidade: quem responde por uma decisão tomada com ajuda de um LLM?

D · Notícias

Assistente para analistas que responde com base nas notícias do dia, que mudam o tempo todo.

Referência: A — RAG (citável, atualizável) + avaliação com perguntas reais. B — fine-tuning de encoder pequeno (BERT/DistilBERT) ou LoRA em modelo pequeno; LLM grande só para rotular dados. C — LoRA com exemplos de textos da empresa (comportamento), ou few-shot como baseline. D — RAG com atualização contínua do índice + busca híbrida.

Leve para casa

  • Prompt é código: estruture, delimite e teste
  • RAG = embeddings + busca + contexto; avalie retrieval e geração separadamente
  • LoRA: $\mathbf{W} + \mathbf{B}\mathbf{A}$ de baixo posto; QLoRA cabe no Colab
  • RAG ensina conhecimento; fine-tuning ensina comportamento
  • Agentes exigem limites; ética e custo fazem parte do projeto
