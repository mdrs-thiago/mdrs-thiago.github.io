Ligando um agente local (Ollama)

Os desafios agênticos (Aula 01, 02 e 07) colocam um LLM de verdade — rodando na sua própria máquina — pra decidir chamar a função que você escreveu. Isso é feito com o Ollama, de graça, sem nenhuma chave de API. Este guia resolve o problema mais comum de primeira tentativa: a página não conseguir "conversar" com o Ollama.

1. Instale o Ollama

Baixe em ollama.com/download (Windows, Mac ou Linux) e instale normalmente. Se você já tem o Ollama instalado, pule pra próxima etapa.

2. Rode o Ollama com CORS liberado

Por padrão, o Ollama só aceita pedidos de localhost — e a página do desafio roda em mdrs-thiago.github.io, um endereço diferente. Por isso precisamos dizer ao Ollama pra aceitar pedidos de qualquer origem, só para este exercício.

Se o Ollama já estiver rodando (ícone na bandeja do sistema/menu), feche-o primeiro — a variável de ambiente só tem efeito se você mesmo iniciar o processo pelo terminal.

Mac / Linux (terminal):

OLLAMA_ORIGINS="*" ollama serve

Windows (PowerShell):

$env:OLLAMA_ORIGINS="*"; ollama serve
Erro comum: digitar LLAMA_ORIGINS (faltando o "O" do início). O Ollama simplesmente ignora a variável — sem avisar — e continua com a lista padrão, que não inclui este site. Confira a grafia com cuidado.

Deixe esse terminal aberto enquanto usa a página do desafio. OLLAMA_ORIGINS="*" não é uma configuração pra deixar permanente — é só pra este exercício local.

3. Confira se pegou

Assim que o Ollama sobe, ele imprime uma linha server config no terminal, com um campo OLLAMA_ORIGINS:[...]. Se aparecer [*], funcionou. Se aparecer a lista longa de localhost/127.0.0.1, a variável não foi aplicada — revise o passo 2.

Ou clique no botão abaixo — ele faz um pedido simples ao Ollama e te diz na hora se está tudo certo:

4. Baixe um modelo com suporte a tool calling

Nem todo modelo sabe decidir "chamar uma função" — precisa ser um modelo com suporte a tool calling. Em outro terminal (o primeiro precisa ficar rodando o ollama serve):

ollama pull llama3.1

Se o llama3.1 não decidir chamar a ferramenta com frequência, tente ollama pull qwen2.5 — outra opção com bom suporte a tools. Troque o nome no MODEL do código do desafio.

5. Como funciona o protocolo de tool calling

Nos desafios, você mesmo escreve o código que conversa com o Ollama — a página só te dá o esqueleto com lacunas. Aqui está o formato exato dos pedidos e respostas, pra você conseguir preencher essas lacunas.

1ª chamada — você manda a pergunta e a ferramenta disponível

POST http://localhost:11434/api/chat
{
  "model": "llama3.1",
  "messages": [
    {"role": "user", "content": "sua pergunta em português"}
  ],
  "tools": [{
    "type": "function",
    "function": {
      "name": "nome_da_sua_funcao",
      "description": "o que ela faz, em texto",
      "parameters": {
        "type": "object",
        "properties": { "arg1": {"type": "number", "description": "..."} },
        "required": ["arg1"]
      }
    }
  }],
  "stream": false
}

Resposta — o modelo decide chamar a ferramenta

{
  "message": {
    "role": "assistant",
    "content": "",
    "tool_calls": [
      { "function": { "name": "nome_da_sua_funcao", "arguments": {"arg1": 3} } }
    ]
  }
}

É aqui que você lê resposta["message"]["tool_calls"][0]["function"] pra saber qual ferramenta o modelo escolheu e com quais argumentos — e então roda a sua função de verdade, em Python, com esses argumentos.

2ª chamada — você devolve o resultado real pro modelo

{
  "model": "llama3.1",
  "messages": [
    {"role": "user", "content": "sua pergunta em português"},
    {"role": "assistant", "content": "", "tool_calls": [ /* a mensagem da 1a resposta, sem alterar */ ]},
    {"role": "tool", "content": "295000.0"}
  ]
}

A resposta dessa segunda chamada traz, em message.content, a resposta final em português — agora baseada no resultado real da sua função, não em algo que o modelo inventou.

Em Python, dentro do Pyodide, você faz esses dois POSTs com pyodide.http.pyfetch — funciona como o requests que você já conhece, só que async:

Com o teste de conexão passando e o modelo baixado, volte pra página do desafio (Aula 01, 02 ou 07). O código já vem com sua função de negócio e o "esqueleto" das duas chamadas — complete as lacunas e clique em "Executar" quantas vezes quiser pra testar e depurar (os print() que você adicionar aparecem ali). Problemas comuns

"Não foi possível conectar ao Ollama" / erro de rede
O ollama serve não está rodando, ou a porta 11434 está bloqueada. Confira o terminal onde você rodou o passo 2.
Erro 403 no terminal do Ollama, ao clicar em testar
CORS bloqueou — quase sempre é a variável OLLAMA_ORIGINS escrita errado ou não aplicada (veja o passo 2 e 3).
"O modelo respondeu sem chamar sua função"
O modelo escolhido não é bom em tool calling, ou teve um dia ruim — tente de novo, ou troque de modelo (veja o passo 4).
Já rodo o Ollama sempre ligado, não quero mexer nisso toda vez
Dá pra configurar OLLAMA_ORIGINS permanentemente nas configurações do sistema (variável de ambiente de usuário) em vez de digitar toda vez — procure "editar variáveis de ambiente" no seu sistema operacional. Não é necessário pra este exercício, só uma conveniência.
