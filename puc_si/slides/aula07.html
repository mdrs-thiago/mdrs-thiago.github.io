Da última aula

Você já sabe processar dados, treinar modelos e montar dashboards. Mas de onde vêm os dados de um sistema inteligente real? Muitas vezes, de sensores no mundo físico — não de um CSV pronto.

Hoje o "input" do seu sistema deixa de ser um arquivo e passa a ser um pino de hardware lendo o ambiente em tempo real.

O que é um Raspberry Pi?

Um computador completo do tamanho de um cartão de crédito: roda Linux, tem Python instalado, se conecta à rede — e ainda tem pinos de entrada/saída para conversar com o mundo físico.

Computador comum

Teclado, mouse, tela — mas sem jeito nativo de ler um sensor ou acender um LED.

Raspberry Pi

Tudo isso, mais os pinos GPIO — a ponte entre o seu código Python e o mundo físico.

GPIO: a ponte entre software e hardware

GPIO (General Purpose Input/Output) são pinos que seu código pode ler (entrada — ex.: um botão, um sensor) ou controlar (saída — ex.: acender um LED, ligar um relé).

  • Digital: só dois estados — ligado (HIGH) ou desligado (LOW).
  • PWM: simula um valor "analógico" ligando/desligando muito rápido (ex.: controlar o brilho de um LED ou a velocidade de um motor).
Não tem uma placa em mãos? A biblioteca gpiozero tem um modo de simulação (MockFactory) — todo o código deste Lab roda igual, sem hardware nenhum.

Lendo um sensor com gpiozero

from gpiozero import Button, LED

botao = Button(2)      # sensor de presença, fim de curso, etc.
led = LED(17)           # atuador: LED, relé, motor via driver

def ao_pressionar():
    led.on()
    print("Sensor ativado!")

botao.when_pressed = ao_pressionar

gpiozero é a biblioteca moderna recomendada — mais simples que a antiga RPi.GPIO, mesma ideia.

Do sensor à decisão

O valor bruto do sensor raramente é o que importa — o que importa é a decisão tomada a partir dele. Essa é exatamente a lógica que você validou no quiz desta aula.

def should_trigger_alert(temperature, humidity, temp_threshold, humidity_threshold):
    return temperature > temp_threshold or humidity > humidity_threshold

# no loop principal do Pi:
temp, umid = ler_sensor()
if should_trigger_alert(temp, umid, 30, 70):
    acionar_ferramenta("notificar_time")   # aqui é onde um agente entraria

Por que isso importa pro seu projeto

Um agente de IA só age tão bem quanto o contexto que recebe. Um Raspberry Pi lendo sensores é uma fonte de contexto do mundo real — e pode ser a ferramenta que um agente aciona para agir de volta no mundo físico.

Lembre do brief da Stonelab: a plataforma agêntica precisa de Uso de Ferramentas e Execução Complexa. Um sensor + uma ação física é só mais uma ferramenta na caixa do agente.
