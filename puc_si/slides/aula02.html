Por que PyTorch, e não só NumPy?

Na Aula 01 você já manipulou arrays com NumPy. Pra treinar uma rede neural de verdade, faltam resolver dois problemas que o NumPy sozinho não resolve:

1. Quem calcula as derivadas?

Treinar uma rede significa ajustar milhares (ou bilhões) de pesos usando cálculo diferencial. Fazer isso à mão é inviável — precisamos de um sistema que calcule gradientes automaticamente.

2. Quem usa a GPU?

Uma GPU pode ser centenas de vezes mais rápida que uma CPU nas multiplicações de matriz que uma rede neural faz sem parar. NumPy roda só na CPU.

PyTorch resolve os dois: o Tensor é quase idêntico a um array NumPy, mas sabe calcular suas próprias derivadas (autograd) e roda em GPU. É NumPy "turbinado" para deep learning.

1. O que é um Tensor?

Matematicamente, um Tensor é uma generalização dimensional. Computacionalmente, é um contentor de dados otimizado para o hardware subjacente.

  • Escalar (0-D): Um único número (ex: $42$).
  • Vetor (1-D): Uma lista unidimensional.
  • Matriz (2-D): Uma tabela (Linhas $\times$ Colunas).
  • Tensor (N-D): Um volume de dados (ex: Imagem RGB é um Tensor 3-D: Canais, Altura, Largura).
A diferença para o NumPy: Tensores PyTorch podem ser processados em GPUs (placas gráficas) para paralelismo extremo e conseguem memorizar as suas próprias derivadas matemáticas. 
import torch

# Escalar
s = torch.tensor(42.0)

# Vetor
v = torch.tensor([1.0, 2.0, 3.0])

# Matriz 2x3 (Aleatória)
M = torch.randn(2, 3) 

# Tensor 3D (ex: Batch de imagens)
img_batch = torch.zeros(32, 3, 256, 256)
print(img_batch.shape) 
# torch.Size([32, 3, 256, 256])

2. Operações e Broadcasting

Operações elemento-a-elemento

Somar, multiplicar ou aplicar uma função a um tensor opera em cada posição, igual no NumPy.

Broadcasting

PyTorch "estica" automaticamente um tensor menor para operar com um maior, sem copiar dados — a mesma regra que você já viu com NumPy na Aula 01.

a = torch.tensor([1.0, 2.0, 3.0])
b = torch.tensor([10.0, 20.0, 30.0])

a + b        # tensor([11., 22., 33.])
a * 2        # tensor([2., 4., 6.])   (broadcasting)

M = torch.ones(3, 3)
v = torch.tensor([1.0, 2.0, 3.0])
M + v        # v "estica" para (3,3) sozinho

# Indexação, igual NumPy
x = torch.arange(10)
x[2:5]       # tensor([2, 3, 4])
x[x > 5]     # filtro booleano

3. Manipulação e Memória Contígua

Em deep learning, estamos constantemente a mudar as formas (*shapes*) dos tensores. Como o PyTorch faz isso sem lentidão?

O Motor em C++

O PyTorch guarda os dados num bloco 1D de memória contígua em C++. Quando usamos view(), não movemos dados na RAM; apenas alteramos a "janela" matemática que olha para esse bloco subjacente.

view() vs reshape()

Se a memória do tensor se fragmentou após uma transposição, view() vai falhar. O reshape() é mais seguro pois fará uma cópia profunda se necessário, mas pode ser marginalmente mais lento.

x = torch.arange(12) 
# [0, 1, 2, ..., 11]

# Redimensionar para Matriz 3x4
y = x.view(3, 4)

# O uso mágico do -1 (Inferência de Dimensão)
# O PyTorch calcula a dimensão restante
z = x.view(-1, 6) # Torna-se 2x6

# Transposição quebra a contiguidade
y_t = y.t()
# z = y_t.view(12)  <- ERRO! (Not contiguous)
z = y_t.reshape(12) # <- Funciona!

4. A Aceleração CUDA (GPU)

Por que usamos GPUs?

Um CPU moderno possui entre 8 a 32 núcleos muito rápidos (ideais para lógica complexa). Uma GPU possui milhares de núcleos mais simples. Como as redes neuronais requerem apenas milhões de replicações de somas e multiplicações independentes (álgebra linear), a GPU processa-as em paralelo de forma fulminante.

Regra de Fogo do PyTorch: Você nunca pode realizar uma operação matemática entre um Tensor na RAM (CPU) e um Tensor na VRAM (GPU). O código irá colapsar com um `RuntimeError`. 
# 1. Detetar Hardware Dinamicamente
device = "cuda" if torch.cuda.is_available() else "cpu"

# 2. Criar e mover os tensores para a GPU
x = torch.randn(2000, 2000).to(device)
y = torch.randn(2000, 2000).to(device)

# 3. Operação Massiva na GPU
z = torch.matmul(x, y) # Instantâneo!

5. Autograd: Diferenciação Automática

O torch.autograd é o motor central de todo o Deep Learning no PyTorch. Ele isenta o cientista de escrever as equações matemáticas do Cálculo Diferencial à mão.

import torch

# Definimos tensores que precisam de gradiente
x = torch.tensor(2.0, requires_grad=True)
y = torch.tensor(3.0, requires_grad=True)

# Fazemos uma operação (Forward Pass)
# Função: f = x^2 * y + y
f = (x**2) * y + y

# Magia Negra! (Backward Pass / Derivada da Cadeia)
f.backward()

# Ver os gradientes (Derivadas Parciais)
print(x.grad) # df/dx = 2xy = 12.0
print(y.grad) # df/dy = x^2 + 1 = 5.0

O Grafo Computacional (DAG)

Define-by-Run (A Vitória do PyTorch)

Antigamente (no TensorFlow v1), tínhamos de definir todo o grafo computacional rigidamente antes de alimentar os dados. O PyTorch revolucionou a IA introduzindo o grafo Dinâmico.

Como Funciona?

O grafo é construído linha a linha, na hora, enquanto os dados passam (Forward Pass). Ao chamarmos .backward(), o grafo é destruído e será recriado na iteração seguinte.

Vantagem Massiva:

Isto permite-nos usar Ifs, For Loops e prints normais de Python a meio da arquitetura, facilitando incrivelmente o *debugging* da rede neuronal.

# PyTorch aceita Python natural
x = torch.randn(1, requires_grad=True)

# O grafo muda de tamanho aleatoriamente!
for i in range(random.randint(1, 5)):
    x = x * 2

if x.item() > 0:
    z = x ** 2
else:
    z = x + 5

z.backward() # Funciona perfeitamente.

6. O que é uma Rede Neural, de verdade?

Um neurônio é só uma equação

Cada "neurônio" calcula uma combinação linear das entradas, mais um viés:

$$y = w_1x_1 + w_2x_2 + \, ... \, + w_nx_n + b$$

Uma camada é várias dessas equações rodando em paralelo. Uma rede é várias camadas empilhadas.

Por que não empilhar só isso?

Empilhar camadas puramente lineares colapsa matematicamente numa única camada linear — não ganha nenhum poder extra. Por isso, entre as camadas, aplicamos uma função de ativação não-linear:

  • ReLU: $max(0, x)$ — zera negativos, a mais usada hoje
  • Sigmoid: comprime para a faixa (0,1) — útil para probabilidades
É a não-linearidade que dá à rede o poder de aprender padrões complexos, não apenas retas.

7. De Tensores a Camadas: torch.nn

Criar manualmente um tensor de pesos pra cada camada funciona, mas não escala. O módulo torch.nn empacota isso em blocos reutilizáveis.

import torch.nn as nn

class MinhaRede(nn.Module):
    def __init__(self):
        super().__init__()
        self.camada1 = nn.Linear(4, 8)
        self.ativacao = nn.ReLU()
        self.camada2 = nn.Linear(8, 1)

    def forward(self, x):
        x = self.camada1(x)
        x = self.ativacao(x)
        x = self.camada2(x)
        return x

modelo = MinhaRede()
print(modelo)

nn.Linear(in, out)

Já cria e inicializa os pesos W e o viés b pra você — é exatamente o $y=Wx+b$ do slide passado, só que pronto.

forward()

Define o caminho que os dados percorrem pela rede. É chamado automaticamente quando você faz modelo(x).

8. Funções de Perda (Loss)

A loss (perda) é um número que mede o quão errado o modelo está. É exatamente o que o autograd deriva para saber em que direção ajustar cada peso.

Tarefa Loss comum Ideia
Regressão (prever um número) nn.MSELoss() Média do erro ao quadrado entre previsão e valor real
Classificação (prever uma categoria) nn.CrossEntropyLoss() Penaliza mais forte quanto mais confiante e errado o modelo estiver
Sem uma loss, não existe o que derivar — e sem derivada, não existe o que otimizar. É a peça que conecta "o modelo errou" a "o modelo aprende".

9. Otimizadores: SGD e Adam

O otimizador é quem de fato usa os gradientes calculados pelo autograd para atualizar os pesos. PyTorch já traz várias estratégias prontas em torch.optim.

SGD (Descida do Gradiente)

A estratégia mais simples: dá um passo de tamanho fixo (learning rate) na direção oposta ao gradiente. Fácil de entender, mas sensível à escolha do learning rate.

Adam

Ajusta o tamanho do passo automaticamente para cada peso, com base no histórico de gradientes. Converge mais rápido na maioria dos casos — por isso é o padrão em boa parte dos projetos.

optimizer_sgd = torch.optim.SGD(modelo.parameters(), lr=0.01)
optimizer_adam = torch.optim.Adam(modelo.parameters(), lr=0.001)

10. O Ciclo de Treino Completo

Juntando tudo que vimos — modelo, loss e otimizador — num ciclo de treino de verdade:

modelo = MinhaRede()
loss_fn = nn.MSELoss()
optimizer = torch.optim.Adam(modelo.parameters(), lr=0.001)

for epoca in range(100):
    # 1. FORWARD: calcula a previsão
    previsao = modelo(x_treino)
    perda = loss_fn(previsao, y_treino)

    # 2. ZERAR gradientes do passo anterior
    optimizer.zero_grad()

    # 3. BACKWARD: calcula os gradientes (autograd)
    perda.backward()

    # 4. ATUALIZAR os pesos
    optimizer.step()
Por que zero_grad() primeiro? No PyTorch, os gradientes somam-se a cada .backward() — não são substituídos. Esquecer de zerar faz o modelo usar a soma de gradientes antigos e divergir.
$$w_{novo} = w_{velho} - \eta \times \frac{\partial L}{\partial w}$$

É exatamente essa conta que optimizer.step() faz para cada peso — o SGD literalmente, o Adam com ajustes adicionais.

11. Dataset e DataLoader

Por que não usar tudo de uma vez?

Com datasets grandes, calcular a loss em todos os exemplos a cada passo é caro e lento. Em vez disso, treinamos em mini-lotes (batches) — pedaços pequenos e embaralhados dos dados.

from torch.utils.data import TensorDataset, DataLoader

dataset = TensorDataset(x_treino, y_treino)
loader = DataLoader(dataset, batch_size=32, shuffle=True)

for epoca in range(10):
    for x_batch, y_batch in loader:
        previsao = modelo(x_batch)
        perda = loss_fn(previsao, y_batch)
        # ... resto do ciclo de treino
shuffle=True embaralha os dados a cada época — evita que o modelo "decore" a ordem em vez de aprender o padrão.

12. Salvando e Carregando um Modelo

Depois de horas de treino, você não quer treinar tudo de novo pra usar o modelo. PyTorch salva o state_dict — um dicionário com todos os pesos aprendidos.

# Salvar
torch.save(modelo.state_dict(), "modelo.pth")

# Carregar (em outra sessão, outro dia)
modelo_novo = MinhaRede()
modelo_novo.load_state_dict(torch.load("modelo.pth"))
modelo_novo.eval()  # modo de avaliação, não de treino

Isso é o que separa um experimento de notebook de um modelo que pode ser reaproveitado no seu projeto integrado.
