Conceitos, Modelos de Serviço e AWS Global Infra

1. On-Premise vs. Cloud

On-Premise (Tradicional)

  • Você compra o hardware (CapEx).
  • Você paga a energia e refrigeração.
  • Você faz a manutenção física.
  • Escalabilidade: Lenta (comprar, esperar chegar, instalar).

Cloud Computing

  • Você aluga o hardware (OpEx).
  • Paga apenas pelo que usa (Pay-as-you-go).
  • Provedor cuida do físico.
  • Escalabilidade: Instantânea (cliques).
"Cloud Computing é a entrega sob demanda de poder computacional, armazenamento e aplicativos via internet com pagamento conforme o uso."

2. Modelos de Serviço

Analogia: Pizza as a Service

IaaS

Infrastructure as a Service

Você gerencia: OS, Dados, Apps.

Provedor gerencia: Virtualização, Servidores, Rede.

Ex: AWS EC2, Google Compute Engine.

PaaS

Platform as a Service

Você gerencia: Dados, Apps.

Provedor gerencia: OS + Infra + Runtime.

Ex: Heroku, AWS Elastic Beanstalk.

SaaS

Software as a Service

Você gerencia: Nada (apenas usa).

Provedor gerencia: Tudo.

Ex: Gmail, Dropbox, Netflix.

3. Modelos de Implantação

  • Nuvem Pública: Infraestrutura compartilhada, acessível via internet pública. (Ex: AWS, Azure). Baixo custo inicial.
  • Nuvem Privada: Infraestrutura exclusiva para uma única organização. Maior controle e segurança, custo muito maior.
  • Nuvem Híbrida: Conecta a infra pública com a privada. Permite transbordamento (cloud bursting) e conformidade de dados sensíveis.

4. Amazon Web Services (AWS)

Líder de mercado em Cloud Computing.

Conceitos Chave:

  • Alta Disponibilidade: Sistemas que operam por longos períodos sem falha.
  • Tolerância a Falhas: O sistema continua funcionando mesmo se um componente falhar.
  • Elasticidade: Capacidade de aumentar e diminuir recursos automaticamente.

5. Infraestrutura Global AWS

A AWS possui datacenters espalhados pelo mundo todo para reduzir latência e aumentar redundância.

Regiões (Regions)

Áreas geográficas físicas separadas. (Ex: us-east-1 N. Virginia, sa-east-1 São Paulo).

Cada região é totalmente isolada das outras.

Zonas de Disponibilidade (AZs)

Datacenters isolados dentro de uma região.

Ligados por fibra de latência ultrabaixa.

Ex: us-east-1a, us-east-1b.

Regiões contêm múltiplas AZs. AZs contêm um ou mais datacenters.

Resumo

  • Cloud transforma o custo de TI de CapEx (Investimento) para OpEx (Operacional).
  • IaaS é o bloco fundamental para administradores de redes.
  • Sempre projete pensando em Regiões e AZs para garantir redundância.
