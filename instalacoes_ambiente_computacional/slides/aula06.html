S3, EBS e Permissões de Acesso

1. Tipos de Armazenamento

Block Storage (Bloco)

Funciona como um HD tradicional. O SO enxerga como um disco C: ou /dev/sda.

Ex: Amazon EBS (Elastic Block Store).

Object Storage (Objeto)

Armazena arquivos "planos" na nuvem, acessíveis via HTTP/URL.

Ex: Amazon S3 (Simple Storage Service).

2. Amazon EBS

Elastic Block Store

"O disco rígido virtual da sua instância EC2."
  • Persistência: Os dados continuam lá mesmo se a instância for desligada (Stop).
  • Vinculação: Só pode ser anexado a UMA instância por vez (geralmente).
  • Disponibilidade: Replicado dentro da mesma AZ.

3. Amazon S3

Simple Storage Service

Características

  • Buckets: "Pastas" raiz onde você joga arquivos. Nomes devem ser únicos globalmente.
  • Objetos: Arquivos (Imagens, Vídeos, Backups, Logs).
  • Durabilidade: 99.999999999% (11 noves). Extremamente seguro contra perda de dados.
  • Site Estático: Pode hospedar sites HTML/JS diretamente!

4. Segurança: IAM

Identity and Access Management

RAIZ DE TUDO: Por padrão, NINGUÉM tem acesso a NADA. Você precisa dar permissão explícita.

Users (Usuários)

Pessoas (ex: thiago) ou Serviços.

Groups (Grupos)

Conjunto de usuários (ex: Admins, Devs). Aplique permissões aqui, não no usuário!

Policies (Políticas)

Documento JSON que define o que pode ou não fazer.

Ex: Allow: S3:ListBucket

Roles (Funções)

Permissões temporárias para serviços (Ex: EC2 acessando S3).

5. Prática Sugerida

  1. Criar um Bucket S3.
  2. Fazer upload de uma imagem (ex: foto do seu cachorro).
  3. Tornar o arquivo Público (via Bucket Policy ou ACL).
  4. Acessar a imagem via navegador usando a URL do S3.
  5. Apagar tudo para não gerar custos!

Resumo do Módulo Cloud

EC2 (Compute)

Servidores virtuais. Use para rodar aplicações, banco de dados, scripts.

VPC (Network)

Sua rede privada. Use Security Groups para proteger as portas.

S3 (Storage)

Armazene arquivos infinitos. Use para backups, mídia estática e logs.
